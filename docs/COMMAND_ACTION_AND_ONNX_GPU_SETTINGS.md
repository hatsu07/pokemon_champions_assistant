# 画面分類ONNXのGPU設定とコマンド画面からの行動提案

## 対戦中の行動提案
- 登録構築の現在のポケモンの4技と、選出3匹のうち現在場にいない2匹を、コマンド画面の時点からAIが比較する。技一覧を開いてから再度AIへ問い合わせることを前提としない。
- 出力は **技名。** または **○○に交代。** （交代技は **技名 → 交代先。**）を基本とし、対戦支援画面の「次の行動」を更新する。
- 戦術判断は引き続きAI。Pythonはローカル登録情報との照合と既知のこだわり固定を検査する。画面に技一覧が実際に表示されている場合は表示内容を優先し、未登録技・未選出の交代先は拒否する。
- コマンド画面上では技の現在PP、封じられた技、実選出未確定の控えは保証されない。推奨と実際の行動結果は別扱い。
- 相手HP/状態/メガ後状態/場/判明技は従来どおり逐次観測とPREPで評価し、試合中のWeb/固定マスター再読込は行わない。

## ONNX推論をGPU優先にする
- 設定 → **画面分類GPU** タブで「自動（GPU優先・利用不可ならCPU）」「DirectML GPU」「CUDA GPU」「GPU優先」「CPUのみ」を選択する。**自動**が初期値。GPU番号は0～7、初期値0。
- Windows配布版はONNX Runtime DirectML版を同梱し、対応GPUで利用できるようにする。WindowsではまずDirectML、次にCUDAが提供されればCUDA、GPUが使えなければCPUを試す。CPU指定時は必ずCPU。明示的GPU指定が利用できない場合は理由を出し、GPUと偽表示しない。
- DirectMLはGPU番号をDirectXのアダプター番号として扱う。GPU番号0が通常のメインGPUだが最速とは限らない。NVIDIA/AMD/Intelで利用できる可能性があり、GPUの有無・DirectX12対応・ドライバー・モデル対応は実機次第。
- ランタイム側で`get_providers()`を確認し、要求GPUが実際にセッションへ有効化された場合だけ **ONNX_GPU_DML** / **ONNX_GPU_CUDA** と表示。それ以外は **ONNX_CPU** と表示。これはローカル分類推論のプロバイダーであり、ChatGPT APIモデルがローカルGPUを使う意味ではない。
- Windows設定の変更は保存したうえで、**次回「自動AI支援開始」時**にローカルモデルを再ロードして反映する。継続中の推論セッションやAPI呼び出しを勝手に差し替えない。
- DirectMLではONNX Runtimeのメモリパターンを無効にし、逐次実行設定とする。Windows以外は従来のCPU ONNX Runtimeを使用する。
- GPU推論速度や45秒ターンの成功率の向上は未検証。BlueStacks上で実測し、GPU側が遅い場合はCPU固定も選べる。

## 回帰検証
- DirectML/CUDAのプロバイダー優先順・GPU番号・起動失敗時のCPUフォールバック・CPUへの静かな切替をGPUだと誤表示しないこと。
- Settingsへの保存・再起動復元、CPU選択中のGPU番号入力無効、既存のChatGPTモデル選択との独立性。
- COMMAND_MENUで技4つまたは控え2匹から一度のAI判断で行動を表示。技一覧未表示でも登録技が有効、未登録技・未選出交代先・既知のこだわり違反が拒否されること。
- オフラインCIはGPUの実機性能、BlueStacks画面の検出率、ゲーム内の技PPや交代可否を保証しない。
