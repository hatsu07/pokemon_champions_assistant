# 行動選択タイマーの早期起動と、ゲーム内時計とのずれの保守的扱い

## 実機報告に基づく問題
画面分類器が行動選択を検出するよりゲーム内ターン時計が約10秒早く始まっており、従来のアプリ側「AI処理開始から30秒」は残り時間を過大評価した。2ターン目では前の時計が残って送信期限切れ、同ターンのAI重複送信もあった。

## 実装方針
- 5分類ONNXの `TURN_ACTION` / `SWITCH_SELECTION` が高信頼（confidence >= 0.95、margin >= 0.50）のとき、**最初の推論フレーム**でタイムスタンプを取り、即座に既存の1回の戦術API処理を開始。低信頼の予測は従来の複数フレーム安定化を継続する。ゲームを自動操作しない。
- イベント画面が表示されたら、ローカルOCRを非同期で直ちに開始（Issue #78、PR #79の機構）。イベント自体はChatGPTへ送信せず、処理済みのメッセージ／HP候補を内部で保持。タイマーOCRは使用しない。イベント⇔演出OTHERの短い交替は正常として扱う。
- 1回行動リクエストを発行した後、イベント画面が見えるまで同じターンの画面を再送信しない。イベントを経て次の行動選択画面が出た時に新しいターンとして時計・送信条件を更新。
- ゲーム内時計は直接取得できない。45秒から報告された検出遅れ約10秒とプレイヤー操作用15秒を確保し、**初回検出から20秒以内**を保守的なAI提案期限とする。API送信を認識完了まで引き延ばさない。実ゲームと正確に同期済みとは表示しない。
- 前ターンの行動提案が後から届いても、イベント解決後・次ターン検出後・保守的なAI期限超過後は古い推奨を表示しない。45秒経過後にもまだ行動可能だと誤認しない。
- GUIには「技選択画面の認識待ち」ではなく「次の行動選択画面の検出待ち」、行動時には「最初のローカル検知から保守的AI締切までの残り秒数」を表示。
- この20秒は**実ゲーム時計の測定値ではなく暫定的な上限**。実機ログでユーザー提供のタイマーと行動提案時刻を突き合わせ、必要ならさらに短縮する。相手イベント画像やプライベート録画はGitHubにアップロードしない。

## 回帰検証
- 最初の高信頼 `TURN_ACTION` フレームで即起動し、同一ターンでは2回呼ばない。
- `BATTLE_EVENT` と `OTHER` が交互に見えてもイベントだけではAI送信せず、次ターンは時計を更新する。
- ローカル認識から20秒を超過したリクエストを送らない。進行中の期限切れ応答／前ターンの古い応答を表示しない。
- Issue #78の非同期OCR・タイマー非依存・イベントメッセージの蓄積と共存する。
- Windows CI／GUIスモークはロジックと起動確認のみ。ゲーム内45秒・実機正確性はBlueStacksで別途確認する。
