# Issue #136: 構築別PREP一括準備と準備状況UI

## 操作

「設定 → 自軍構築」で登録構築を選択し、「選択構築のPREPデータを一括準備・再開（試合前）」を押す。AI通信に同意した後、従来の全対面解析に加え、8工程の状態を表示する。

1. 構築6匹・CSVの整合性
2. Champions固定マスター／根拠不足
3. 構築別対面カタログ
4. 完全に同一の型署名・根拠を持つ評価の差分再利用
5. 未評価セルだけを構造化AI解析（API上限・中断・再開あり）
6. PREP11/6項目に利用可能な根拠の検査（完全に埋まらなければ一部完了）
7. 構築専用LIVEマトリクス・60秒ルックアップの生成・更新
8. 4ファイル読込形式と6×相手候補高速索引の整合性検査

保存済み進捗は \`<data_root>/live-team-assets/<team_id>/prep-progress.json\`。構築CSV SHA、現在の工程、工程の状態、理由、通信回数、今回追加数、生成物fingerprintを保持する。途中で停止・失敗した場合に既存の解析済み提案を破棄しない。アプリを再起動しても終了未確認の「実行中」を「停止（再開可能）」として表示する。

## 構築別表示

登録構築の一覧に「PREP準備」を追加。各構築の保存済みmanifestとmatchup-evidenceから、構築一致・マトリクス/ルックアップのSHA整合・旧評価数・AI v2仮説数・根拠不足・品質認証の有無を確認できる。選択した構築の工程別履歴と充足情報は詳細欄に表示する。

**UIでの参照は読み取り専用。** 状態確認だけでマトリクス生成・AI通信・SQLite移行を始めない。試合中も、UIの状態参照からLIVEファイルにアクセスしない。構築名・team ID単位で結果を分離し、型変更により古い対面の評価が一致しなくなれば「再準備が必要」と表示する。

## 安全な完成判定

- \`matrix_compatible=false\`、\`matrix_provisional=true\` でも、構築一致と戦術未検証を区別する。
- AI提案は、\`AI_PROPOSAL_UNVERIFIED\`。ゲーム内採用技・確定KO・安全なハード交代・確定処理役には昇格させない。
- 「8工程が完了」と「Champions根拠が全部揃うこと」と「実戦PREPが完成」は異なる。初手11項目、控え6項目が根拠付きで実際に判定できなければ「一部完了」として残す。
- 相手6匹・自軍選出3匹が確定してから初めて、実戦用18対面と温存／停止／締め3点を評価する。キャッシュ18枠だけでは実戦PREP完成とはしない。
- 共通の4ファイル凍結読込を変更しない。LIVE中に5番目のファイル／SQLiteを読まない。
- ダメージ・相手最大打点・SAFE/PROCの自動検証エンジンは #44 の依存課題。現在は、事前収集済みの固定根拠・条件付きヒントの範囲を超えて完全PREPを約束しない。

## PR #137 レビュー反映（2026-10-30）

工程実行、評価根拠、生成物一致は相互に独立した状態として管理する。

- **工程実行状態**：全工程の実行が正常に終了した場合は \`run_status=完了\`。固定マスター不足、AI仮説の未認証、\`live_ready=False\` はこれを \`一部完了\` へ強制的に下げない。API通信上限により未解析件数が残る場合は \`一部完了\` とする。
- **評価根拠状態**：\`evidence_status\` と \`quality_ready\` に分離。AIが未検証である限り、工程が完了していても戦術品質は別判定。
- **再開履歴**：\`team_id\`・CSV SHA・Championsマスター集合版が一致すれば、前回の工程記録と累計カウンタを引き継ぎ、試行履歴を別保存する。環境／レビューなどのfingerprintが変わった場合は古い評価状態を失効させる。根拠版が違う過去の成功を現行準備として表示しない。
- **一致判定**：\`csv_match\`（CSVファイル実体のSHA）と \`tactical_match\`（登録型署名と保存済み生成物の一致）を別表示。CSVの非署名欄だけ変更して旧対面素材の再利用が可能でも、古い実行進捗の \`再準備が必要\` を消さない。
- **環境鮮度**：保存manifestの\`environment_source_sha256\`と現行スナップショットの実体SHAを比べる。更新後は古い生成物を自動で有効化せず、再準備理由を表示する。
- **停止操作**：AI解析完了後も工程境界で中断要求を検査し、公開前・公開処理後・高速索引検査中に停止要求が来た場合、未完了工程を完了と誤記録しない。途中まで保存されたAI提案は次回再利用できる。すでに原子的に完了した保存操作を取り消したとは表示しない。

**検証上の注意：** Windows CIによるオフラインテスト／GUI起動と、ユーザー実機でのPREP完成率・時間内入力・戦術精度は別段階。前者の成功だけで後者を保証しない。


## 2026-10-30 再レビュー（v1/v2評価件数・元ソース鮮度）

- \`ai_proposal_cells\` は重複除去済みの**v1/v2合計**として維持。追加した \`ai_v1_cells\`（文章提案）と \`ai_v2_cells\`（構造化提案）はキー（相手、構築枠）を単位に排他的に数え、両方ある場合は**検証済みv2提案を優先**する。旧manifestに合計だけある場合、v1/v2内訳は**未確認**として表示する。
- 根拠カタログの \`CONFIRMED\` 件数は \`confirmed_cells\` としてAI提案や既存 \`CONDITIONAL\` と分離表示する。これらは実戦PREP11/6項目の完全性と同義ではない。
- 派生manifestに元LIVEマトリクスSHA、元60秒ルックアップSHA、基準構築の解析後署名SHA、人間レビューの入力SHAを保存し、設定画面で現行入力と**読み取り専用**比較する。旧manifestに証拠が欠ける場合も準備完了扱いしない。環境スナップショットとChampions固定マスターの鮮度照合も維持する。
- 工程6「PREP根拠の検査」→工程7「条件付きAI注記の公開」の順で実行し、UIに示す順序と統一する。
- 回帰テストはv1のみ／v2のみ／同一対面v1＋v2重複、元マトリクスのみ変更／元ルックアップのみ変更／基準構築変更／人間レビュー変更／古いmanifestの入力根拠欠落を扱う。

この改善はデータの**分類とソース鮮度表示**に限る。対面AIの推測・確定不能なKO、安全受け、処理役を確定判定へ昇格させない。


## 2026-10-30 第4回再レビュー（生成キャッシュと現行版の選択）

- \`matchup_evidence.SOURCE_FILES\`（使用可能ポケモン、技、習得技）の**3つのファイルSHAを生成fingerprintとmanifestに含める**。生成物が残っていても、この根拠が変わった場合は旧 \`matchup-evidence.json\` をキャッシュヒット扱いせず、試合前に別fingerprintで再生成する。旧版は破壊しない。
- v2仮説の差分再利用は既存の \`team_matchup_reuse\` が \`master_sha256\` と個別 \`evidence_key\` で検証する。マスターの版が異なるv2仮説は機械的に移行しない。
- \`team_readiness\` は登録型署名だけでなく、**Champions固定マスター3件、元LIVEマトリクス、元ルックアップ、基準構築、レビュー、Singles環境**が現行入力に一致し、生成物SHAも健全な候補を優先する。現行一致が1件もなければ最新の候補から失効理由を説明する。選出画面/対戦中にデータ再生成はしない。
- 環境 A→B→A、人間レビュー A→B→A の切り戻しでは、古い版Aが現行ソースと一致するなら準備済み表示へ復帰できる。manifestの更新時刻だけで選ばない。
- 新規テスト：固定3マスターの1件ずつ更新→失効→再準備→新カタログのSHA確認→元に戻して旧版キャッシュヒット。環境・レビューのA→B→Aを回帰確認。

依然として、条件付きのAIヒント・暫定LIVE評価は対戦時の確定KOや安全受けを保証しない。


## 2026-10-30 第5回再レビュー（レギュレーションのみ変更）

- \`SET_FIELDS\` の戦術型署名には \`reg\` を含めないままとし、生成manifestに**登録6匹の \`MON.reg\` 値**を別途 \`team_regulations\` として記録。カタログの \`regulation\` は従来どおり先頭MONの値。
- 読み取り専用 \`team_readiness\` は候補を選ぶ前に、\`catalog.regulation\` および \`manifest.team_regulations\` と現在の構築CSVを照合する。型署名・固定マスター・環境・レビューが同じでもレギュレーションが異なれば「再準備が必要（レギュレーションが変更されました）」と表示し、旧評価を使用可能としない。
- A→B→Aへの切り戻しでは、現行レギュレーションAに一致する旧A生成物を優先し、生成時刻が新しいBを誤って選ばない。先頭以外のMONのみ \`reg\` を変更した場合も失効させる。
- 旧manifestに \`team_regulations\` がなければ未確認として再準備が必要。対戦中にファイルを確認しないという従来のルールは維持する。
- 回帰テストでは **進捗journalがない** 条件を明示し、CSV SHAチェックに頼らない規制判定を確認する。

未検証の技・KO・安全受け・処理役の認証は行わない。


## 2026-10-30 第6回再レビュー（構築内のレギュレーション矛盾）

- 正本は **\`TEAM.reg\`**。6匹の \`MON.reg\` すべてがTEAM行と一致する場合だけ、その単一レギュレーションのPREP素材を生成する。空欄で統一された7行のみ \`UNDECLARED\` として扱い、TEAMのみ指定、MONの混在、一部空欄を不整合として拒否する。
- 登録・再検証 \`team_management.validate_team_document\` は矛盾を \`INVALID\` とする。 \`team_live_assets.prepare_team_assets\` はファイル生成前に \`ConfigurationError\` で停止する。 \`team_prep_readiness.team_readiness\` は読み取り専用のまま \`構築確認不可\` と理由を表示する。
- manifestへ \`team_regulation\`（TEAMを正本とする単一値）と \`team_regulations\`（各MON値）を保存し、既存のカタログ \`regulation\` と照合する。旧manifestに正本情報が欠ける場合、準備済みと判定せず再生成を要求する。
- 回帰テストは、全7行一致、混在MON、TEAM行のみ変更、一部MON空欄、全7行空欄（UNDECLARED）、一致したA→B→Aへの切り戻しを検証する。旧版生成物は破壊しない。

レギュレーションが矛盾するファイルから1匹目の値を推測しない。確定不能な処理役・安全受けの認証にも利用しない。
