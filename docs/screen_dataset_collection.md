# Pokémon Champions 画面分類モデル用の学習データ収集アプリ

このツールは **開発用** です。学習済みの画面分類モデル、ランクマ支援の完成品ではありません。ゲームへの操作は行わず、ユーザーが指定したWindowsミラーリングウィンドウ/ADBのROIを読み取り専用でキャプチャします。ChatGPTへの画像送信も行いません。

## Windowsでの起動

GitHub Actionsの検証済み **`PokemonChampionsScreenDataCollector-DEVELOPMENT-windows-x64`** を取得しZIPを展開、`PokemonChampionsScreenDataCollector.exe` を起動します。CLI起動の場合は `python scripts/windows_screen_dataset_collector_entry.py` です。

キャプチャ対象の設定は通常の対戦支援アプリと共有されます（標準：`%LOCALAPPDATA%/PokemonChampionsAssistant/config/settings.json`）。先に通常アプリの「設定 → 画面キャプチャ」で**実際のスマホミラーリングウィンドウ・ROIを保存**しておきます。モデル・ログイン・自軍構築はデータ収集に不要です。画面が再生成され、保存済みのウィンドウIDが古くなった場合は収集アプリの「ミラーリングウィンドウを選び直す」でユーザーが明示的に選択します。

## 収集手順

1. ミラーリング画面を表示。収集アプリで撮影対象・ROI・保存先を確認する。
2. 一試合（プライベートバトルなど）につき**一つの収集セッションID**を使用する。新しい対戦に入る前に「次の対戦セッションを作成」を押す（この操作で未保存候補は破棄される）。
3. 「このゲーム画面のローカル収集を明示的に許可する」をチェック。「自動収集開始」を押すと、約1秒間隔で**画像候補をメモリに集めるだけ**。自動でディスクに保存・クラウド送信・AI分析はしない。
4. 選出画面・技選択画面・交代画面など、必要な画面を表示させる。最大150候補で上限に達すると収集を停止する（古い候補を勝手に消さない）。1枚だけ必要なら「1枚撮影」。
5. 「収集停止」を押し、一覧の画像をクリックしてプレビューを確認する。複数画像を選択してラベルを決められる。
6. 画面の**実際の内容を人間が確認し**正しいラベルを選択。「選択候補をこのラベルでローカル保存」→確認ダイアログで同意。これで初めてPNGが作られる。不要な候補は「破棄」。保存後の訂正は「保存済み画像の誤ラベルを訂正」から行う。
7. 新しい対戦に移る場合は、収集停止・必要画像の保存後、**必ず新しい対戦セッション**を開始する。最低でも複数の独立した対戦・演出パターンを集める。

## 正解ラベルの考え方

| ラベル | 正解として分類する場面 |
|---|---|
| `MATCHMAKING` | マッチング待ち、対戦準備 |
| `TEAM_SELECTION` | 選出3匹を実際に選ぶ画面 |
| `MOVE_MENU` | 技のコマンドを実際に選べる画面 |
| `PARTY_MENU` | 交代先を選べる画面 |
| `BATTLE_EVENT` | 攻撃・交代・メッセージ等の演出中 |
| `RESULT` | 勝敗・対戦終了画面 |
| `UNKNOWN` | その他・判定不能・タイトル/メニュー画面など |

特に**「6匹表示」だけでTEAM_SELECTIONにしない**こと。3匹選ぶ操作ができるかを確認します。戦闘中のメッセージも技選択画面と間違えないよう確認します。曖昧な画面を無理に正解ラベルへ分類せずUNKNOWNを使います。複数画像の一括保存も選択したものがすべて同じラベルであることを確認してください。

## 保存場所・プライバシー

初期保存先：`%LOCALAPPDATA%/PokemonChampionsAssistant/private-training/screens/`（ユーザーが変更可能）。

形式：`screens/<LABEL>/<match-session>__<image-id>.png`。元フレームはメモリ内で長辺960px以下に縮小され、保存された画像は人間が明示選択したPNGのみです。フレーム数は最大150/収集セッション（古い候補は自動削除しない）。保存済みPNGはアプリを終了しても残るので、不要なら自分で削除してください。

データセットのPNG、動画、学習済みモデル候補は通常の対戦ログやGitHub/CIに含めません。リポジトリの`private-training/`は.gitignoreで除外しています。画像の権利・共有条件にも注意してください。

## モデルの学習とリリース判定（別工程）

データ収集GUIは **ラベル付けまで** を担当します。GPU学習は別スクリプト `scripts/train_screen_classifier.py` で行い、ユーザーPCのNVIDIA GPUが学習に使える場合は利用できます。学習用PyTorch/TorchVisionなどは配布GUIに含めません。

例（依存導入済みの学習開発環境で明示実行）：

```powershell
python scripts/train_screen_classifier.py --data-dir "$env:LOCALAPPDATA/PokemonChampionsAssistant/private-training/screens" --output-dir private-training/output --epochs 12 --device auto
```

学習スクリプトは**対戦セッション単位で学習/評価を分割**し、正解ラベルごとの再現率・適合率を算出します。初回は `validated=false` の実験モデルとして保存されます。対戦時間内の検出遅延・誤認識を独立したミラーリング実機テストで確認するまで正式配布しません。 `scripts/check_screen_model_release.py --release` が通らない限り、モデル付き正式版を名乗れません。

## 動作確認の最低条件

- 初回起動だけで画像は保存されず、収集開始には許可チェックが必要
- キャプチャプレビューがゲーム内の選択したROIと一致する
- 150枚を超えてメモリが増えない、ウィンドウ再生成や撮影失敗で自動保存しない
- ラベル未指定の保存が不可能、手動確認後にのみPNG作成
- 次の対戦でセッションIDが変わり、対戦ごとの学習/検証分割が可能
- キャプチャ開始やラベル付けではChatGPTへ送信しない

現行のWindows CIは合成画像でこれらの操作と起動を検証します。実スマホミラーリングの画面認識モデルの精度やGPU学習速度は**未検証**です。
