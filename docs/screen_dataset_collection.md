# Pokémon Champions 画面分類モデル — 未ラベル画像の連続収集と人手ラベル付け

このWindows GUIは、実スマホミラーリング画面から**選出・技選択・交代・演出などの学習データを作る開発用ツール**です。ゲーム操作・ChatGPT送信・自動ラベル推定は行いません。

## 起動と収集

1. Windows CIの `PokemonChampionsScreenDataCollector-DEVELOPMENT-windows-x64` を展開し、`PokemonChampionsScreenDataCollector.exe` を実行します。通常の対戦支援アプリで保存済みのWindowsネイティブ撮影/ADB設定とゲームROIを共有します。
2. 実際のスマホミラーリング画面が対象になっていることを確認し、必要に応じて「ミラーリングウィンドウを選び直す」を使用します。
3. 対戦ごとに新しい記録セッションIDを作成します。同じ対戦内ではIDを変えないでください。過去の未ラベル画像や確定済みラベルは保持されます。
4. **収集速度を選択**します。標準5fps（200ms間隔）、2fps（500ms）、10fps（100ms）を指定できます。撮影処理・JPEG書込・PC負荷が大きい場合は指定fpsに達しないことがあります。
5. **未ラベル画像用の容量上限**を2/5/10 GBから選択（初期2 GB）。書き込み先の空き容量512MiBを確保するよう監視します。容量に達すると理由を表示して自動収集を停止しますが、過去の画像を勝手に削除しません。
6. 「このゲーム画面を未ラベル画像としてローカルディスクに自動保存することに同意する」をチェックしてから「自動収集開始」を押します。撮影成功のたびに未ラベルJPEGがローカルに保存されます。**150枚到達では停止しません**。ラベル付けやウィンドウ操作のために対戦中に中断する必要はありません。
7. 対戦終了時に「収集停止」を押します。画面には今回の収集枚数と未ラベル画像の合計容量が表示されます。

## 後から正解ラベルを付ける

- 「未ラベル画像を再読込」で対戦セッションを選択できます。保存した候補は**100枚ずつのページ**で一覧表示し、画像を選ぶとプレビューされます。アプリ終了後も保存した未ラベル画像を読み直せます。
- 同じラベルの候補を複数選択（Ctrl/Shift）し、正解ラベルを人間が決めて「選択画像を正解ラベルでPNG保存」を押し、確認ダイアログで承認します。ラベル確定したJPEGは、学習用のPNGを正常保存した後にだけ未ラベル領域から消します。
- 「選択した未ラベル画像を破棄」は明示確認が必要で、実行後の画像は復元できません。誤分類済みPNGのラベルは「保存済み正解ラベルを訂正」で変更できます。
- 未ラベル候補が多い場合は各ページを進めて確認してください。学習に必要な画面を選別することを優先し、似た画像を無理にすべてラベル付けする必要はありません。

## 保存場所と学習互換性

初期保存先：`%LOCALAPPDATA%/PokemonChampionsAssistant/private-training/screens`

- **未ラベルJPEG**：`screens/_UNLABELLED/<対戦セッションID>/<撮影時刻>_<画像ID>.jpg`
- **人が確定した正解ラベルPNG**：`screens/<LABEL>/<対戦セッションID>__<撮影時刻>_<画像ID>.png`

学習スクリプトは5ラベルのPNGのみ収集するため、未ラベル画像は自動で学習データに混ざりません。既存の1,032枚などのラベル済みPNGは変更されません。

| ラベル | 画面 |
|---|---|
| `TEAM_SELECTION` | 選出3匹と初手を入力できる画面 |
| `TURN_ACTION` | 各ターンの行動・技選択が可能な画面 |
| `SWITCH_SELECTION` | 自主・強制交代先の選択画面 |
| `BATTLE_EVENT` | 技・特性・持ち物・交代・メガ・能力変化など新たな情報を読み取れるイベント画面 |
| `OTHER` | 待機・対戦結果・意味のない演出など上記以外 |

分類ルール、旧データの安全な移行、旧ONNXの非互換性は
[5分類仕様とデータ移行](SCREEN_LABELS_FIVE_CLASS_MIGRATION.md)を参照。
`UNKNOWN`は教師ラベルではなく、低信頼推論の未判定値だけに用います。

同じ試合から取得した類似画面が学習側と独立評価側へ分かれないよう、**別の対戦では新しいセッションID**を作ります。マッチング画面にポケモン6匹が表示されても、3匹を選ぶ操作ができなければTEAM_SELECTIONとしません。

## 注意と検証の範囲

この変更は**未ラベル画像の自動保存にユーザーの明示同意を求めます**。これまでの「メモリだけに保持し、ラベル付け後にだけ保存」とは異なります。無人で共有・アップロード・AI送信する機能はありません。

WindowsのオフラインCIは合成画像と一時保存先で保存・容量・人手ラベル・GUIのページ分割を検証します。実際のミラーリング環境における指定fpsの達成、長時間書込速度、正解ラベルの精度は別途実機確認が必要です。

## 学習開始

データ収集GUIは、未ラベルJPEGを収集・対戦後に人がラベルを確定するところまでを担当します。
`_UNLABELLED` は学習には使いません。5ラベルのPNGが各ラベルで独立した複数セッションに
揃っていることを、学習前の検査で確認します。

### CPU / NVIDIA CUDA Docker学習

WSLターミナルで次を実行します。`%LOCALAPPDATA%` 配下の `screens` は読み取り専用で
Dockerへ渡され、ONNX、JSON、重みキャッシュはローカルの無視対象
`private-training/` 配下だけに作成されます。パスに空白または日本語が含まれていても、
起動スクリプトが一つの bind mount として扱います。
trainer ではリポジトリ全体も読み取り専用です。`TRAINING_DATA_DIR` を指定する場合も、
データをワークスペース外に置いてください。出力とTorchのキャッシュだけが
`private-training/` の個別書込み mount です。

```bash
# 画像数・セッション分離・画像読取を先に検査する（ネットワーク不使用）
./scripts/train_screen_classifier_docker.sh --validate-only

# CPU学習（既存の動作）
./scripts/train_screen_classifier_docker.sh --epochs 12

# GPU学習前にDocker内部でCUDA利用可否を確認
./scripts/train_screen_classifier_docker.sh --gpu --check-gpu

# GPUで1エポックの試験学習
./scripts/train_screen_classifier_docker.sh --gpu --epochs 1

# GPUで12エポック、ImageNet重みを明示的に利用
./scripts/train_screen_classifier_docker.sh --gpu --epochs 12 --pretrained
```

通常の `dev` イメージやWindows/WSLホストへ PyTorch/TorchVision/ONNX は導入しません。
通常の `trainer` はCPU専用です。CUDA学習では独立した `trainer-gpu` と
CUDA 12.1版PyTorchを使用します。Docker Compose `gpus: all` とDocker Desktop WSL2 GPU連携が必要です。
WSLで `nvidia-smi` が成功してもDockerのGPU対応が保証されるわけではありません。
`--gpu --check-gpu` の `"cuda_available": true` を確認してください。
CUDAが使えない場合GPUモードはCPUにフォールバックせず失敗します。
初回のGPUイメージは大容量なので空きディスク容量を確認してください。
VRAM不足の場合は `--batch-size 8` を指定できます。
画像検査は枚数・経過時間、学習・検証はバッチ進捗を表示します。
学習時の画像全件チェックは1回だけにしました。学習処理は画面、
ラベル、生成モデルを外部へ送信・アップロードしません。`--pretrained` を付けた場合だけ、
第三者配布のImageNet重みをローカルキャッシュへ取得します。GPUの実機学習成功・高速化・精度は、RTX 3060 Ti実機で別途検証が必要です。
実データを使わない専用CIは、5ラベル・4独立セッションの合成画像でCPU 1エポック学習、
ONNX出力、SHA-256、未検証マニフェスト、ONNX Runtimeの5出力推論だけを確認します。
通常のWindows検証には組み込みません。

詳細は `scripts/train_screen_classifier.py`、正式同梱前チェックは
`scripts/check_screen_model_release.py --release` を参照してください。合成データによる
学習パイプラインの確認と、実機Champions画像の精度・速度検証は別工程です。

## 5分類ONNXマニフェストv2と、既存学習結果の安全な修復

5分類学習器は今後`schema_version=2`でONNXに隣接する
`champions_screen_classifier.json`を出力する（旧7分類の`schema_version=1`は引き続き拒否）。
2026-10-24以前の学習器では、**5分類のモデルでも誤ってv1を書き出す不整合**があった。
保存済みモデルは**再学習なし・元モデル無変更**で新しい兄弟フォルダーにコピーして修正できる。

WSLのリポジトリからDocker devコンテナ経由で実行（モデルはローカルのみ）。
実際の`run-...`名は学習結果の`output`に置き換える。

```bash
SOURCE="private-training/output/run-20261024T004230Z-webSrxET"
DEST="${SOURCE}-schema-v2"

# デフォルトは検査のみ。元ONNX/JSONは変更されない。
docker compose run --rm --user "$(id -u):$(id -g)" dev \
  python scripts/upgrade_five_class_model_manifest.py \
  --source-dir "$SOURCE" --destination-dir "$DEST"

# 明示承認後に、*新しい*フォルダーへ2ファイルをコピーする。
# コンテナがrootでホスト所有の出力先へmode 0700フォルダーを
# 作らないよう、WSLの自分のUID/GIDを明示する。
docker compose run --rm --user "$(id -u):$(id -g)" dev \
  python scripts/upgrade_five_class_model_manifest.py \
  --source-dir "$SOURCE" --destination-dir "$DEST" --apply
```

以前のコマンド（`--user`なし）で作成したモデルフォルダーに
`ls: Permission denied` が出た場合は、WSLで所有者と権限を確認する。

```bash
stat -c '%U:%G %a %n' "$DEST"
# root所有だった場合に限り、**変換先フォルダーだけ**を自分のUID/GIDへ修復
sudo chown -R "$(id -u):$(id -g)" "$DEST"
ls -lah "$DEST"
```

変換済みのフォルダーを消したり、`--apply`をもう一度実行する必要はない。
モデルは個人のローカル保存物なので、`chmod 777`で全員公開しない。
今後の変換処理も、ホストが非root所有の出力先にrootで書こうとする場合は
`OUTPUT_OWNER_MISMATCH`で中断する。

修復ツールは元manifestの5ラベル完全一致、v1、入力寸法、評価指標、
ONNXのSHA-256を確認する。**旧7分類・破損・順序不一致を拒否**。
修復結果の`validated`は必ず`false`であり、
学習結果の`quality_gate_passed=false`を覆さない。
新フォルダーのONNXとJSONを**両方セットで**Windows側ローカル
`private-training/models`へコピーし、画面収集GUIの
「実験ONNXモデルを選択」で新しい`.onnx`を選ぶ。
これは**自動ラベルの候補生成専用**であり、ランクマの正式画面分類へ昇格しない。
学習済みの元アーカイブ、ユーザー画像、教師PNGは変更・送信しない。

## 対戦後の自動ラベル候補・一括承認（PR #25）

この機能は**正解ラベルの自動確定ではありません**。収集済みの未ラベルJPEGを、
対戦セッション単位で画像類似度・時刻・AI予測の一致性によりグループ化し、
AI候補を人が目視し、保存前の最後の確認画面でラベルを承認してから正解ラベルPNGへ保存します。

1. 対戦後に収集を停止し、対象の対戦セッションを選択します。
2. AIなしでも「この対戦を解析・グループ化」を押すと、画像の類似性だけで連続グループを作れます。この場合ラベルは「要確認」のままで、AIの代わりに人がラベルを選びます。
3. AI推定するには、まず本プロジェクトのDocker GPU学習結果
   `private-training/output/champions_screen_classifier.onnx` と
   `private-training/output/champions_screen_classifier.json` を、
   **両方セットで**Windows PC上のローカル専用フォルダーへコピーします。
   WSLのリポジトリ内から実行する例：

   ```bash
   APPDATA_PATH="$(powershell.exe -NoProfile -Command '[Environment]::GetFolderPath("LocalApplicationData")' | tr -d '\r')"
   MODEL_DIR="$(wslpath -u "$APPDATA_PATH")/PokemonChampionsAssistant/private-training/models"
   mkdir -p "$MODEL_DIR"
   cp private-training/output/champions_screen_classifier.onnx private-training/output/champions_screen_classifier.json "$MODEL_DIR/"
   ```

4. Windows収集アプリの「実験ONNXモデルを選択」から上記 `.onnx` を開きます。対応する `.json` が同じフォルダーに必要です。マニフェストのSHA-256・正規化パラメータ等を検証し、不一致なら推定しません。開発用の候補生成に限って `validated=false` のモデルを使えます。通常の対戦支援アプリは引き続き未検証モデルを拒否します。
5. 「この対戦を解析・グループ化」を押すと**オフライン・別スレッド**で解析し、処理枚数を表示します。最大30枚ごと・画像差分・撮影時刻の飛び・モデル予測変化によりグループを区切ります。弱い予測は「要確認」として扱い、正解ラベルの `OTHER` と区別します。
6. グループを選ぶと代表3枚（先頭・中央・末尾）に加え、**グループ内の全画像（最大30枚）のサムネイル一覧**を時系列で表示します。各画像にはAI予測・信頼度・⚠要確認（未知の画面、予測信頼度不足、前後との画面差分等）を表示します。サムネイルをクリックすると拡大プレビューへ切り替わるため、途中に挟まった別画面を探せます。⚠はAIの警告であり、⚠がない画像も正解保証ではありません。
7. **一部の画像だけ誤っている場合**：サムネイルをCtrl/Shiftで複数選択し、サムネイル一覧直下の「グループ／選択画像の訂正先ラベル」で正解ラベルを選んで「選択した画像だけラベル訂正」を押します。グループ全体のラベル訂正より、画像単位の個別訂正が優先されます。「選択画像を一括保存から除外」では対象JPEGを残したままPNG保存対象から外せます。訂正・除外を取り消すこともできます。

8. **グループ一括訂正とPNG保存を分離**：グループ一覧でCtrl/Shiftで1件以上を選択（または「すべてのグループを選択」）し、複数グループを同じラベルに変える場合は「グループ／選択画像の訂正先ラベル」でラベルを選んで **「選択グループのラベルを一括訂正」** を押します。これは**仮訂正のみ**で、PNGはまだ保存しません。元のAI候補・個別訂正・除外JPEGは保持され、グループ一覧やサムネイルに保存予定のラベルが表示されます。元のAI候補が正しければ、ラベルを訂正する必要はありません。その後、**「選択グループをPNG保存」** の**1ボタンだけ**で、選択中の1件または複数グループを保存できます。グループごとに異なるラベル（元のAI候補または個別に仮訂正済みラベル）も維持します。最終確認ダイアログにグループ別ラベルと枚数、部分訂正数、除外数が表示され、「はい」で保存、「いいえ」でJPEGのまま保持します。旧「選択グループをAI候補で承認・PNG保存」「選択ラベルに訂正してグループ保存」の2ボタンは廃止しました。下部の「選択画像を正解ラベルでPNG保存」は従来の**手動・画像単位**の保存機能として別に残します。

9. 保存前に、選択グループ内の**未確定ラベル、全画像除外、重複ファイル**を検査し、いずれかがあれば**1枚も保存せず中断**します。AI候補や⚠付き画像のラベルが間違っていないか、サムネイルや元画像を人間が見て確かめてください。人間が確認しないままAI予測を確定すると誤った教師データになるため、チェック操作の省略は正解確認の省略を意味しません。保存には`UnlabelledScreenStaging.label()`を用い、成功したJPEGだけを未ラベル領域から削除します。未保存グループ・AI予測・部分訂正・除外を維持し、再解析は行いません。保存途中のディスクエラーでは成功済み画像だけがPNG化され、失敗・未処理画像はJPEGとして残ります。未保存画像に対する確認チェックの再要求はありません。

**ウィンドウの幅変更**：画面の幅を狭くすると複数ボタンの横並びを縦配置に自動切替し、画像プレビューも領域に合わせて再縮小します。縦方向はスクロールして操作できます。狭い画面で操作ボタンがウィンドウ外にはみ出さないことをCIのオフスクリーンQtテストで確認します。

10. 承認済みデータをGPU再学習するときは、Windows収集アプリの「承認済みデータをGPU再学習（WSLで明示実行）」を押します。初回はWSLターミナルで `pwd` を実行したLinux絶対パスを入力し、確認ダイアログで明示承認します。`wsl.exe` の別プロセスでDocker GPU学習を起動し、GUIに進捗ログ・保存先を表示します。WSLが利用できない場合は「GPU再学習コマンドをコピー」で端末から実行できます。学習中は収集アプリを閉じないでください。

   ```bash
   bash ./scripts/train_screen_classifier_docker.sh --gpu --epochs 12 --pretrained --archive-output
   ```

   `--archive-output` により `private-training/output/run-日時-ランダム文字/` に個別保存され、以前のONNXとJSONは上書きしません。再学習後は**別の独立した対戦**で精度を検証し、モデルをWindowsのローカルフォルダーへ再コピーしてから次の候補生成に使用します。未検証モデルを自動的に正式アプリへ同梱・昇格させません。

**精度上の注意:** ユーザーの**旧7分類モデル**の初回GPU事前学習済み12エポック結果では、
`TEAM_SELECTION` の適合率約95.5%、`BATTLE_EVENT` 約44%、
`MATCHMAKING` の再現率0%、`UNKNOWN` の再現率約20.5%でした。
独立した検証セッションは2件のため、将来の対戦への汎化は未検証です。
これらの値は旧7分類の履歴であり、5分類の精度を示しません。新5分類モデルは再学習・実機検証が必要です。予測信頼度0.90以上でも正解とは保証しません。**一括承認前の目視確認を省かないでください。**

すべてローカル処理で画像・モデルをAPI、GitHub、CIに送信しません。GPUは**学習**に使用し、Windows GUIでのONNX推論はCPUで実行します。ミラーリング実機での分類精度、総処理時間、人間の確認負担の削減率は別途計測が必要です。
