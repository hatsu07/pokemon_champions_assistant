# Pokémon Champions プロジェクト運用指針 — Codex向け再構成版 v2.7

> **出典と限界**：この文書は現在のプロジェクトで共有されているユーザー定義の運用方針をCodexが実装・テストできるよう、意味を保持して再構成したもの。ChatGPTプロジェクト設定画面から指示全文を機械的にエクスポートした原本ではなく、**逐語一致・完全収録を保証しない**。対戦判断ルールの唯一正本は `masters/Pokemon_Champions_MC_live_decision_gate.txt`。この文書はそれを上書きしない。

## 目的と責任分離
- 『Pokémon Champions』シングルランクマッチの**長期勝率と再現性**を高める。選出3匹全体の勝利可能性を優先し、対戦→記録→分析→修正→再戦を回す。
- 戦術判断（3匹＋初手、18対面PREP、技・交代先・メガ、試合後の振り返り）はすべてOpenAI API。Pythonは観測、ローカル確定計算、合法候補列挙・検証、イベント記録、状態同期、表示だけ。**ゲーム操作は人間が行う**。
- 公式、固定マスター、ゲーム内の最新共有情報、Champions専用統計などの出典を区別する。他作品の種族値・技・効果等をChampionsへ類推流用しない。「確定・推定・不明」を区別する。

## 情報の優先順位・鮮度
- 固定情報：使用可能ポケモン/種族値/タイプ、特性/道具/技/習得技、自軍構築、LIVEマトリクス、60秒ルックアップ、判断ゲート。
- 動的情報：使用率、ポケモン別技・特性・道具・性格・配分の採用率、よく組まれるポケモン、レギュレーション、環境変化。通常の構築分析では最新確認し、取得日・レギュレーション・出典を併記する。
- 優先：Champions公式／HOME等公式／ユーザー共有の新しいゲーム内表示／専用統計／大会・上位考察／その他。最新ゲーム内情報とWeb統計が矛盾するなら前者を優先する。
- 動的採用率は相手個体の型確定に使わない。過去のスナップショットは「その日付の参考資料」であり、現在の確定情報ではない。
- **LIVE対戦中はWeb検索、固定マスター再読込、詳細型調査、重いダメージ計算をしない**。

## 試合開始の4ファイル実読込（LIVE正本が最優先）
試合開始や次戦開始ごとに、以下4件の**本文を今回の開始操作で実際に読み込み**、成功/失敗を個別に記録。既保持要約・過去試合・存在確認・ファイル名・ハッシュだけで代替しない。4/4成功時のみ「事前ロード完了」。
1. `Pokemon_Champions_MC_live_decision_gate.txt`
2. `Pokemon_Champions_MC_live_selection_matrix.txt`
3. `Pokemon_Champions_MC_60sec_lookup_master.txt`
4. `Pokemon_Champions_MC_team_2026-10-03.csv`（現行構築を明示変更したときだけ差替え）
構築履歴 `2026-09-29` を自動で選ばない。**同じ試合のマッチング後や対戦中に再読込しない**。4件の本文はその試合中不変のキャッシュとして扱う。

## 選出・40秒PREP
- 相手6匹を受けたら、マトリクスの対応する**6行を一括取得**し、素早く「選出：A / B / C　初手：A」を返す。選出前Web・詳細検索なし。選出後の変更提案なし。
- 相手の主要先発・積み/高速エース・壁/起点・こちらの処理役・終盤役・温存・一貫性・安全受けを評価。主要候補に明示処理役ゼロなら補完枠を最大1回比較。「保険/○」は明示処理役に格上げしない。
- 選出回答**直後**から40秒PREP：0–8秒は18対面をキャッシュ済み6行から抽出、8–23秒は初手×6、23–35秒は控え2×6、35–40秒は温存・積み停止・締めの勝ち筋3点を固定。各対面の必要項目はLIVEゲートを参照。
- マトリクスを第一参照。ルックアップは矛盾・重大警戒等のみ**原則2対面まで**。6匹全体を再検索しない。詳細型・精密計算・低頻度分岐で40秒を延長しない。未完なら支援ミス扱いで完了宣言しない。相手初手が出たらPREPを即停止。

## 試合中の入出力と判断順序
- UIは見た目で `PARTY_MENU` 共通検出。通常交代/とんぼ等交代技/ひんし後/道具特性交代の**理由**は直前イベントと状態FSMで判定。
- 入力機会IDはゲームターン数と別。とんぼがえりの予定交代先はOpenAIの先行判断が現在も有効なら再利用、変化時はOpenAIへ再照会。ランダム強制交代で選択UIがなければその瞬間のAPI要求なし。死に出しと次の技判断は別入力機会になり得る。
- 毎ターン先に行動のみを表示。技名、`○○に交代。`、交代技は`技名 → 交代先。`が原則。緊急注意が必要なら短く1文。説明は試合後。
- 確認順：現在盤面/即負け筋 → 先制技と優先度 → 実測S → メガ後タイプ/相性 → こだわり固定 → 積み/起点 → 行動保証 → 温存 → 相手残り/終盤。
- 交代前に今の場から即KOできないか確認。相手を倒す役と安全受け出し先は別。いかくを特殊受け性能の根拠にしない。
- こだわり技固定は交代まで続き、固定中に別技を推奨しない。使用技の打点と固定後の一貫性を比較。
- 通常技が先に動ける/耐えて撃てるかを確認してから先制技を比較。メガ変化時は変化後タイプ/特性/S/耐性を更新。最終1対1はHPを0にできる勝ち筋を要する。
- HP・状態異常・能力ランク、判明技/特性/道具、S、場・天候・壁・ステロ、交代情報、フォーム/メガ、行動保証と技固定は、観測済みを失念せず次判断に送る。
- 45秒/ターンの入力時間を尊重し、調査より**現在の高期待値行動を期限内に返す**ことを優先。LIVEゲート内にさらに高速制限があればそれに従う。

## ローカル効果・証拠・継続ターン
- 技・特性・持ち物のChampions専用マスターで**候補効果を計算**し、技成立・発動テキスト・HUD等で実際の成立を確認。技を見ただけで追加効果や能力上昇を断定しない。
- `がくっと/がくーんと/ぐーんと/ぐぐーんと`等は**観測用の戦闘メッセージ辞書**に登録可能。ただし実画面の文言を検証するまで確定辞書にしない。結果はマスターによる効果計算と突き合わせ、重複反映を防止。
- 天候/フィールド/壁は仕様確定済みの期間のみカウント。相手延長道具が不明なら候補集合で追う。ターン終了確定時に一回だけ減算し、交代選択/技演出/同一ターンの入力窓では減算しない。ステロ等は解除まで別管理。
- 画面情報と状態が矛盾すれば訂正イベントを追加し再投影。過去に送信したAPI入力スナップショットは改ざんしない。未確定状態を確定と表示しない。

## 試合後レビューと反復改善
- 終了後：選出、初手、各ターン、勝ち筋、負け筋、情報の取り方、リスク管理、構築要因、プレイヤー要因、支援側ミスを別々に検証。結果論でなく**その手の開始時点の既知情報**で評価。
- ログ：日付、勝敗、双方の選出、主要行動、判明情報、重要分岐、改善案、人間対戦/CPU疑い/不明。対戦ログや環境履歴はオフライン分析で参照し、LIVE中には探索しない。
- 同じ負け方・同じ支援ミスの再発防止。複数試合で検証し、変更優先は立ち回り → 選出 → 技 → 道具 → 配分 → 1匹 → 複数匹。1戦だけで構築を大改造しない。
- O/X評価は `docs/Pokemon_Champions_CODEX_OX_Postmatch_Method_v2_7.md`。**LIVE中にO/X追加計算を入れない**。既存ゲートで防げたミスはルール不足ではなく実行ミスとして記録。

- 正本・ノウハウ・過去の教訓が競合したら、当該LIVE判断ゲート/実戦で新たに確認した事実を優先し、他は保留・改善候補として分離する。
