# Implementation decisions

## Phase 0/1 — 2026-10-21

- Added a Python `src/` package and an offline CLI only. It reports that live capture, OpenAI API use, and game control are not configured or implemented. No input injection code exists.
- The SQLite store is append-only for raw observations, semantic events, confirmed-effect markers, turn ends, and API request snapshots. The only state authority is deterministic replay; cached projections are auditable derivatives.
- Semantic evidence is explicit about source, certainty, and supersession. Equal-priority contradictory facts remain `CONFLICT`; candidate evidence does not become confirmed. The reducer accepts no unobserved Champions mechanics.
- Duration candidates decrement only for a uniquely persisted `TURN_END_CONFIRMED`. A duplicate turn ID or effect instance is rejected in the same SQLite transaction as the corresponding event marker.
- API request persistence is transport-free in this phase. A future Phase 3 adapter must first freeze the exact v2.3 payload and reserve its `(match_id, decision_window_id, tactical_state_version, allowed_action_digest)` key.
- `private_history` is excluded from the Docker build context and Git ignore rules. `inspect-history` only lists XLSX sheet structure and first-row cell kinds/values, preserves source SHA-256, does not modify files, infer column semantics, import rows, or send data anywhere.

### Historical workbook mapping proposal (not executed)

Any user-approved future import should preserve every source cell as raw provenance and use the composite identity `(source_sha256, workbook_sheet, row_ref)`. Column meanings must be confirmed by the user after the read-only structural report; no automatic mapping to battles, opponents, or outcomes is permitted. The live-match loop and OpenAI prompts must never read these workbooks.

## Phase 2 — 2026-10-21

- `MasterPreloader` is the only component that reads the four LIVE masters. It reads all four on every new-match operation, hashes and freezes their body text, rejects partial loads, and builds in-memory exact-name indexes. Sessions retain only frozen assets and never reread master paths.
- The session model separates observed game turns, decision windows, and observations. UI classifiers provide only `VisualUI`; `PARTY_MENU` meaning is assigned by append-only semantic event history, never by separate image recognizers.
- Local code determines legal choices, freshness, deadlines, deduplication, and plan validity only. It does not rank actions. Scripted responses are test/simulation fixtures and must be replaced—not extended with tactics—by the Phase 3 API adapter.
- A pivot plan is reusable only when its observed-state signature is unchanged and its target remains in the complete current switch candidates. Any state difference or incomplete/illegal candidate set requires a new decision request or blocks the recommendation.
- Non-normal party windows do not assume an input timer unless observation supplies one. The Phase 2 synthetic trace applies the required 90-second selection, 40-second PREP, and 45-second normal-command budgets; a future capture adapter must replace these caps with a smaller actual UI remainder where available.

## Phase 3 — 2026-10-21

- The v2.3 JSON Schema files in `contracts/` remain the only local wire-contract authority. `structured_schema.py` builds a distinct, closed-object/all-required Responses Structured Outputs copy at send time because the API accepts a strict Schema subset. A transport result must pass both that API constraint and a second validation against the original v2.3 Schema.
- `contract_validation.py` is deliberately a safety validator, not a tactical engine. It rejects mismatched IDs/digest/version, stale or closed windows, unavailable moves, choice-lock violations, unavailable Mega, illegal switch/pivot targets, invalid faint `keep_back`, and incomplete PREP18/WIN3 claims. It never changes a returned choice to a locally preferred one.
- The real transport is `OpenAIResponsesTransport`, but mock is the normal default. Real sends require `CHAMPIONS_ASSIST_ENABLE_OPENAI_API=1`, a separate runtime API key and model setting, positive request and spend bounds, and an explicit estimated per-request cost. These names are intentionally unrelated to Codex/IDE configuration. The SDK client uses `max_retries=0`; the adapter does not add tactical retries.
- API snapshots contain only the canonical request payload. API response/usage tables are append-only and exclude API-key parameters. Estimated spend is an explicit guard value, not inferred from volatile published pricing; actual provider token fields are recorded when available. A failure/timeout consumes an estimated external-request budget conservatively because it may have reached the provider.
- Prompt construction has no master-directory argument. It uses match-frozen bodies and indexes from Phase 2, places the frozen LIVE gate first, puts observed data in a JSON data envelope, and never enables OpenAI tool calls or web/file lookup. Matrix rows are already in the canonical request; lookup excerpts are restricted to at most two named PREP rows in accordance with the gate.
- `session_payloads.py` provides the current Phase 2-to-v2.3 bridge. Its `READY_CONFIRMED` synthetic default is appropriate only for existing simulated tests; Phase 4 must replace it with real reducer/readiness/watermark evidence rather than treating unknown UI state as confirmed.
- `api-smoke --real-api` is intentionally an explicit, potentially paid one-SELECT diagnostic. Its no-flag path refuses locally. It was not invoked with `--real-api` in this implementation.

## Phase 4 — 2026-10-21

- The observer accepts RGB `Frame` objects through one read-only interface. Image-directory, video and synthetic sources execute in Docker; `WindowsNativeFrameSource` is the primary live selection and `AdbScreenshotFrameSource` is an explicit fallback. Neither has been tested on Windows/BlueStacks, neither discovers a window or guesses coordinates, and neither includes game-control code.
- ROI coordinates are normalized, versioned calibration data. The repository intentionally carries no candidate Champions coordinates, UI templates, or claimed Japanese text dictionary. `TemplateUiClassifier` recognizes exactly the v1.4 visual categories only. Its `PARTY_MENU` output contains no reason, and `DETAIL_OVERLAY`/`MOVE_MENU` preserve an existing normal input opportunity in the FSM.
- OCR is an adapter boundary. Tesseract is invoked only on changed configured ROIs; `MappingOcrEngine` supplies deterministic synthetic labels. The parser performs exact frozen-team/opponent term lookup plus only caller-configured regex patterns. It has no fuzzy correction, no SV knowledge, and no fallback mechanics inference. Frozen team vocabulary is assembled from the already frozen match assets, never from a live filesystem read.
- OCR text creates raw evidence and optional semantic candidates. A move/ability/item activation enters `PENDING_EFFECT`; a distinct configured confirmation with the same `effect_instance_id` is required for `CONFIRMED_EFFECT`. The frozen effect catalog can identify a Champions rule/provenance but cannot itself confirm a present-match activation or calculate an unmapped effect.
- Same-message frames are one display episode. A blank or changed ROI ends that episode, so an identical later phrase is independently auditable. Retained frames can be OCR-reanalysed with revised calibration rules as appended evidence; manual corrections append `MANUAL_VERIFIED` evidence and supersede prior IDs rather than altering history or frozen API snapshots.
- `ObserverPipeline` records capture/observed/processed watermarks and calls the existing Phase 2 state update only for normalized facts/explicit legal candidates. That advances `tactical_state_version` and marks waiting/recommended answers stale. It owns no model transport and therefore cannot block capture while an API request is in flight.
- `observer-replay` is an offline calibration utility for images, video or deliberately labelled synthetic fixtures. It saves/loads ROI files and reports UI correctness, event miss/false-positive counts and processing latency. Its output always says that real-game validation is false; it performs no paid API call, web access, capture activation or game input.
- OCR runtime evidence for the Docker image: Tesseract 5.5.0, Apache-2.0 engine, distro-owned `jpn.traineddata` (2,471,260 bytes). No OCR binary/model is vendored. Windows packaging must independently verify the selected binary, language data size and all license/notice obligations.

## Phase 5 — 2026-10-21

- `desktop.py` is a presentation/coordinator boundary. It reads a detached session/replay projection, never parses frames or runs tactical logic, and a paint/refresh event cannot schedule an API request. Only the explicit user/API-runtime queue method can emit an immutable `DesktopModelJob`.
- The job contains the v2.3 payload, frozen assets, identity tuple and an API epoch. `DesktopModelDispatcher` executes a supplied adapter callable in a `QThread`; `AdapterJobExecutor` opens its own SQLite connection instead of sharing the GUI store connection. The GUI applies a returned `DISPLAYABLE` answer only after it verifies the unchanged current identity and epoch. Emergency stop changes the epoch, so an in-flight result is discarded while capture/logging can continue.
- The normal desktop executable binds an empty mock transport by default and is API-stopped. Selecting `--real-api` does not weaken Phase 3 guards: a user must still use the visible API control and provide all explicitly enabled runtime environment limits/key/cost settings. API keys have no GUI field, `QSettings` key, SQLite column, export value, or log path.
- Manual corrections use the existing `MatchSession.update_observed_state` API with `MANUAL_VERIFIED` and `CONFIRMED`/`CANDIDATE` quality. A late actual-three/lead correction has the same evidence path, rebuilds only the already-frozen PREP input, clears its prior PREP result as `ACTUAL_SELECTION_CORRECTED_REPREP_REQUIRED`, and never selects a replacement locally. Therefore correction is new evidence, not an in-place mutation of event history, frozen masters or sent snapshots. The existing state-version update is the sole stale-recommendation mechanism; the GUI does not advance it during redraw and clears any cached review after a changed correction.
- Match history exports include source hashes but intentionally omit frozen master text and never accept an API secret. Normal removal is an append-only `MATCH_HIDDEN_BY_USER` event. A separate permanent-purge method requires the exact selected `match_id`, refuses the active match, and is exposed only behind a typed GUI confirmation; this narrowly scoped privacy action is documented as an exception to runtime ledger retention.
- PySide6 Essentials was selected for the core Widgets/Gui runtime rather than the full optional WebEngine/PDF bundle. Docker adds `libdbus-1-3`, `libegl1`, `libgl1`, and `libxkbcommon0` solely for offscreen development tests. This does not settle Windows PyInstaller dependency collection, Qt licensing notices, or MSI contents.
- The manually dispatched Windows workflow now emits a separate `PokemonChampionsSettingsValidation` PyInstaller `onedir` artifact.  It packages only the fixed catalogue needed to validate a locally supplied team CSV, opens the existing desktop in `--settings-validation-only` mode, and disables match-start/API-send controls.  It is an operator-run pre-MSI validation tool, not a Phase 7 deliverable; GitHub Actions must still demonstrate that the frozen Qt runtime starts, and a BlueStacks operator must report the actual preview result.
- The GUI demo is explicitly synthetic: its blank `SyntheticFrameSource` item is not a Champions frame, and model replies are Phase 3 mock fixtures. It demonstrates wiring and stale/duplicate-safe display only. Windows/BlueStacks capture, true OCR quality, actual timer input, deployment and terms validation remain Phase 6/7 work.

## Phase 6 — 2026-10-22

- Windows capture remains a read-only boundary. `Win32WindowGeometryProvider` finds only a caller-specified visible title and refreshes its client screen-pixel rectangle for every frame; it reports missing, minimized and invalid-client states instead of retaining old coordinates. DPI is recorded when Windows supplies it. It never launches, restores, resizes, focuses or closes BlueStacks, and no successful pixel read is labelled as a Champions validation.
- `WindowsNativeFrameSource` uses title/identity-selected Win32 `PrintWindow` off-screen client rendering for a target window; an explicit desktop rectangle remains a diagnostic-only Pillow path. `AdbScreenshotFrameSource` is a separately selected fallback whose only commands are `get-state` and `exec-out screencap -p`. There is no ADB input, shell tap/keyevent, launch, port-forward or LAN exposure implementation. Both adapters remain unverified for continuous BlueStacks observation.
- `CaptureWorker` is a framework-neutral background worker. It recreates an explicit frame source after an unavailable target so start/exit/minimize/restore/resize handling can be measured without blocking widgets. It shares neither a GUI object nor a SQLite connection; worker-owned observer processing must publish immutable notification data. `DesktopObserverBridge` only queues a display refresh and optional latency mark, and cannot request an API call or advance tactical state by itself.
- Phase 6 reports use monotonic p50/p95/max summaries for capture lag, intervals, recovery, capture-to-observer and capture-to-GUI stages. Frame-drop counts are explicitly interval estimates and are `null` unless the operator provides an expected FPS. A missing stage remains `null`, not zero. Windows-native and ADB reports may be compared, but the code makes no backend recommendation.
- `ValidationDataset` is local labels plus evidence metadata, not embedded media. It supports synthetic, recorded-Champions and live-Windows-Champions categories, and `observer-replay` recalculates an optional supplied source digest (or ordered still-image manifest) before a real-evidence admission gate can pass. It requires all twelve requested scenario labels. UI/event/OCR results are evaluated against the existing replay output. Even a fully labelled attested, hash-matched dataset reaches only `READY_FOR_HUMAN_REVIEW`; it never automatically approves Phase 7.
- The portable Windows GitHub Actions artifact is a manually triggered PyInstaller `onedir` validation harness for a user who has no development Python installation. It is explicitly not an MSI or release proof, uploads no private media by default, and runs only `--version` on the runner. Windows dependency collection, OCR bundling, installer, upgrade/uninstall and live validation remain Phase 7/on-device work.
- Phase 6R treats the operator-reported BlueStacks 5.22.285.1013, Android 13 beta, landscape 1920 × 1080 and Android 240 dpi configuration as a reference environment only. A native probe must separately record the actual grabbed image dimensions, Win32 client rectangle and `GetDpiForWindow` value; Android density is neither inferred from nor substituted for Win32 DPI. A single explicit local first-frame export may feed the manual ROI tool only after a successful read-only capture report and operator confirmation that the saved pixels are Champions.
- The first on-device Phase 6R checkpoint met that narrow condition: the operator-supplied local `PrintWindow` report recorded a 2254 × 1298 px client/image, DPI 192, per-monitor-v2 awareness and 47 ms first-frame acquisition; visual inspection showed the Champions title screen without a desktop overlay. This is capture-path evidence only. It neither turns `CAPTURED_READ_ONLY_UNVERIFIED_CONTENT` into a battle/OCR acceptance nor permits fixed ROIs, rules, API traffic or game control.

## GUI settings v2.8 — 2026-10-22

- Settings persistence is a separate typed JSON model, not `QSettings` window geometry and not runtime OpenAI configuration. It uses version `1.0`, atomic same-directory replacement, a last-known-good backup and dependency-injected paths for Docker tests. Its schema rejects secret-like keys; runtime API settings remain environment/credential concerns.
- A selected capture target persists a descriptive HWND/PID/title identity but is re-enumerated before preview. A stale, recreated, hidden or minimized target cannot be reused by title alone and never causes a desktop-capture fallback. Preview is a one-frame worker task; it performs no OCR, state update, decision-window transition or API request.
- The current on-device first-frame evidence is intentionally not promoted to a calibrated ROI. GUI ROI values are normalized user calibration candidates, require a new calibration after size/DPI changes, and do not establish Champions UI recognition.
- Team registration copies user CSVs to the configured private data root, preserves raw fields and validates only fixed master facts. NFKC is used strictly for label comparison (for example full-width ASCII digits), never to rewrite saved CSV text or infer a move/item/form. Incomplete AP/nature coverage yields `NEEDS_REVIEW`; `INVALID` and `SOURCE_MISSING` cannot become a live next-match source.
- A pending storage/team configuration is applied before `MatchController.start_match`, which forces a fresh four-file read and SHA freeze. Existing session assets and sent snapshots have no writable route to the pending configuration. A storage database switch checkpoints first, then blocks the old DB-bound model worker until application restart rather than allowing it to continue on an old path.
