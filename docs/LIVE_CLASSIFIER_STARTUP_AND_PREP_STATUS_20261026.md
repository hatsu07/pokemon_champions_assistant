# ライブ画面AI送信とPREP進捗表示（2026-10-26）

## 実戦ログからの修正理由
ユーザー提供のローカル診断ログで、画面分類モデルからの検出証拠がない状態で
`FALLBACK_SCREEN_RECHECK` と `FALLBACK_TRANSITION_DEFERRED` が繰り返された。
非操作画面に対する頻繁な画像API送信は、45秒ターンの判断遅延やAPI費用増加につながる。

## AI支援開始時の確認
- 4つのLIVEマスター本文の新試合での読込とSHA記録は既存の `_new_match` が実行する。
- `_start_auto` は4つのSHAが無い場合は警告を表示し、AI送信開始を認めない。
- 検証済み5分類ONNXがロードできない場合は、ユーザーに使用不可理由、
  低頻度画像変化確認の精度・費用リスクを明示して `Yes/No` の同意を求める。
  **モデルが無いことだけでは自動AI送信を禁止しない**（最新ユーザー要望）。
- モデル利用中はローカル5分類 `TEAM_SELECTION`/`TURN_ACTION`/`SWITCH_SELECTION`
  のみを自動AIトリガーとし、`OTHER`/`UNKNOWN`/`BATTLE_EVENT` はAIへ送信しない。
  イベント分類だけで技・特性・道具の事実を確定しない。
- モデル未設定モードでは画像変化ベースの確認を残すが、最小間隔と再送抑制を適用。
  これは操作画面の確定を意味せず、誤送信ゼロやターン内返信を保証するものではない。

## 分類モデル設定
対戦支援画面の「画面分類モデルを設定」ボタンから、検証済みの5分類モデル
`champions_screen_classifier.onnx` と検証マニフェスト
`champions_screen_classifier.json` のあるフォルダーを選択する。
両ファイル、schema v2、5ラベル一致、チェックサム、validatedフラグなどを確認した場合のみ採用。
フォルダーは %LOCALAPPDATA% 以下のアプリ設定領域
`screen_classifier_choice.json` に保存し、次回起動時に再読込する。
ONNXがなければ利用不能と示すだけで、自動ダウンロードや偽モデル生成はしない。
旧7ラベルPNGや元画像、秘密情報は変更・公開しない。

## PREP進捗
`PREP` 専用の大きなステータス表示を用意し、
「選出待ち・処理中・事前評価完了（構造確認）・部分完成・未完成/中断/エラー」を区別する。
可能なら評価済み対面数、期待対面数、勝ち筋の担当3点、実選出未確認を明記する。
キャッシュが18件存在することと実戦妥当性・実選出3匹の確認は同一視しない。
有効なPREPソースは固定LIVE判断ゲートと現行構築・マトリクスを維持する。

## 操作部品
選出・技選択・交代の手動キャリブレーションボタン、
画像の手動AI送信ボタン、PREPの手動再実行ボタンをライブ画面から削除。
キャプチャの開始・停止、4ファイルロード、分類モデル設定とログ出力は維持する。
ゲーム操作は依然としてユーザー自身が行う。

## 検証範囲と制約
オフラインQt GUIとモック分類器の回帰テストは、実際のBlueStacks画面精度や
Championsでの45秒行動提案を保証しない。実機テストではPREP表示、
開始前警告、操作画面でのAI起動、非操作画面送信件数、AI消費量を再計測する。
マージ条件はPRの最新HEAD SHAに対するWindows CI全体と必須jobのSuccess。
