# OCR → ライブ状態更新（18項目） / 2026-10-27

## 主要な変更

- ローカルOCR候補は取得後に対戦状態へ届くまで未接続だったため、`live_state_updates.apply_local_ocr`をキャプチャ側へ接続した。外部通信を必要としない。
- 画面分類が `BATTLE_EVENT` の場合に加えて、`TURN_ACTION` / `SWITCH_SELECTION` の名前HUDやHP、設定済みPP領域をバックグラウンドOCRへ渡す。捕捉ループはOCR完了を待たない。
- 固定4ファイル読み込みは従来どおり必須。任意の**Champions専用技マスター**が試合開始前に存在するときだけ変化技カテゴリを追加で凍結し、挑発下での技合法性検査へ利用する。試合中のファイル再読込は禁止。
- 繰り出し、現在名前、明確な技使用、瀕死、HP、PP、状態異常の付与と解除、能力ランク変化、アンコール/挑発/かなしばり、持ち物の消費と特性の発動、天候/フィールド/双方の場の効果を同じイベント更新器へ接続。
- 未判明相手枠がちょうど1個で、公式で使用可能な**凍結マトリクス上**の新種が相手側繰り出しメッセージで確認できた場合にだけ補完。凍結対面キャッシュの3行を取り込み、存在しなければ未評価。順位や安全受けを作り出さない。
- 観測技と未知技を区別し、現在の持ち物状態・特性・状態変化をポケモンごとに保つ。提案した技や交代を実行済みとは扱わない。
- 交代前後のアクティブとOCR観測の改訂番号を管理し、新しい観測が入った後に返ってきた古いAI回答を棄却。回答受信とは別にGUI描画イベントを記録。
- 同一の連続OCR文字列を重複入力してPP/ランクを二重計上しない。OCR内容の重複判定キーは文字列ではなくハッシュのみを保存する。

## 根拠と認証範囲

- 確認済みOCRであるための条件：信頼度0.72以上、構築/マトリクス上の一意なポケモン名、規定の明確なメッセージ形式、矛盾のない対象側。低信頼は候補にとどめる。閾値だけでゲームでの正しさを保証するものではない。
- `observed_move` は**その試合で認識された候補**であり、そのポケモンが未公開技を持たないという証明ではない。アイテム消費履歴と現在所持は別の欄。
- PPを実数値として反映するには、ゲーム内HUDに合わせて `own_pp_move1`～`own_pp_move4` の `PP_FRACTION` ROIを明示的にキャリブレーションする必要がある。サンプル座標を創作しない。残りPPが0と明確なら使用を禁止、その他はUNKNOWN扱い。
- 挑発中の**変化技**だけは試合開始前に凍結したChampions技マスターのカテゴリで判定する。カテゴリ不明は推測で禁止しない。アンコールは前に使用した自軍技が確認済みならその固定に従う。かなしばりは対象技まで判明した場合のみ直接禁止。
- メガ/フォルム/現在タイプは既存の画像観測フィールドを引き続き保持するが、**未確認の変更後タイプ・素早さなどを別作品で推定しない**。相手未公開特性、持ち物、技、PPはUNKNOWNのまま。
- 天候やフィールド、壁、アンコール等の継続ターンはゲーム内から明確な残りターン数を確認できない限り `None`（UNKNOWN）にする。ターン数を固定で仮定して自動解除しない。
- 実ゲームの全メッセージ表記は未収集。パーサーの対応は明確な日本語文字列の安全な一部に限定し、将来提供された実ゲームOCR原文から拡張する。誤った型推定より情報保留を優先。

## テストの対象

- 相手の繰り出しによる未知枠補完と凍結キャッシュ再利用
- マリルリ交代の実観測更新、技固定解除、相手の判明技
- HP/PP=0、状態異常付与・解除、ランク上昇と交代時リセット
- アンコール、挑発（Champions変化技カテゴリ）、天候・フィールド、持ち物消費・特性発動
- 連続OCRの重複排除、低信頼OCRの保留、古いAI結果の無効化
- Windows CIは実ゲームOCRの正解率を保証しない。BlueStacks上で実戦の文言・遅延・合法手・画像0枚を別途検証する必要がある。
