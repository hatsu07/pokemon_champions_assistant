# AI開発エージェントの作業方針・CI検証契約

この文書は GitHub 上の Codex / ChatGPT / その他の AI 開発エージェント、および人間の開発者に適用する。**各タスク開始時に `AGENTS.md` と本書を読み、実装・テスト・報告に適用する。** 本書は Pokémon Champions 固有のゲーム仕様、LIVE マスター、既存契約に優越しない。

## 最重要：CI とコミットの整合性

**CI が成功したかではなく、「PR の最新 HEAD コミットを対象にした CI が成功したか」で判断する。** 以前のコミットの成功、部分的なジョブ成功、実行中の CI、キャンセルされた CI を最終検証に使用してはならない。

標準手順：

1. 作業ブランチと **Draft PR** を使用する。仕様確認、実装、既存テスト、新規回帰テスト、ドキュメント更新を行う。
2. ローカルまたは許可された環境で利用可能なオフラインテストを実行し、問題を修正する。実行できないテストは正直に未実行と記録する。
3. 全変更をコミットする。対象 PR の **HEAD SHA を記録**し、この時点を検証対象として固定する。
4. PR を **Ready for review** にする（または最新コミットに対して `synchronize` で自動起動された CI を使う）。必要なCIを実行する。CI起動後に追加コミットしてはならない。
5. CI 完了後に `PR head.sha`、`workflow_run.head_sha`、実際に checkout/build した `git rev-parse HEAD` が同一であること、および **すべての必須ジョブが成功**したことを確認する。
6. 最新 SHA に紐づく成功が確認できてから初めて「CI確認済み」「ビルド検証済み」と報告する。実機/ゲーム内動作を確認していなければ、それも明記する。

CI中に修正が必要になった場合：

- 実行中の結果は **旧リビジョンの参考情報**に格下げする。
- PR を Draft に戻して修正し、テスト・コミットをすべて終える。
- **修正後の最新 SHA** について CI を最初から再実行する。古い CI の `rerun` は新 HEAD の検証にならない。
- CI結果、run ID、対象 SHA を照合し直す。必要であればこのサイクルを繰り返す。
- 実行中に新しいコミットが混入した場合、以前の CI が成功しても古いリビジョンの結果として扱う。

## 2026-10-23 マージ事故後の厳格な停止条件

PR #30をCI全体がFailure（GitHub Actions Artifact容量超過）のままmasterへマージしたのは誤り。**これ以降、必須CI全体が最新SHAで`completed/success`以外なら理由を問わずマージ禁止。** ユーザーの最新判断により有料GitHubのBranch protectionは不要。サーバー側のマージ禁止設定をCI検証の前提にせず、最新SHAに対するCI workflow全体・必須ジョブのSuccessを厳守する。GitHubが`mergeable=true`でもCI未成功なら例外を認めない。

PRのCIテスト・Windowsビルド・両GUIスモークと、手動要求されたArtifactsの配布を分離する。ArtifactsはPRではアップロードしない（容量上限はコードテストと無関係）。`workflow_dispatch`の`publish_artifacts=true`で**明示的に別操作で**配布を試行する。配布に失敗した場合は配布失敗として報告する。CI成功を配布成功と混同しない。

GitHub privateリポジトリの`master.protected=false`は既知の制約で、ユーザーは有料プランや物理的マージ保護を希望しない。**GitHub側の自動マージ拒否はない**。エージェントが最新PR HEAD・CI全体・必須Windowsジョブの`completed/success`を毎回確認する。詳細・新チャット引継ぎは`docs/CI_MERGE_GUARD_AND_NEXT_CHAT.md`。

## リポジトリ側で実装する保護

`.github/workflows/windows-validation-artifact.yml` では、Ready PR の新規作成・再オープン・追加コミット（`synchronize`）・レビュー可能化で Windows 検証する。Draft では高額な Windows ビルドを開始しない。同一 PR の古い実行をキャンセルする。

CI は明示的に PR の `head.sha` を checkout し、配布アーティファクトのアップロード直前にも GitHub API で **その時点の最新 PR HEAD** を確認する。不一致なら失敗とする。ビルド成果物には対象コミットの識別子を同梱する。

**これらは作業ミスの防止策であり、GitHub のマージ制御そのものではない。** PR/branch protection または repository rulesets で最新 SHA の Windows 必須チェックを Required にし、失敗時のマージを禁止することが望ましい。設定可否と実際の有効状態は別に確認すること。管理権限がなく設定不能なら「未設定・未確認」と明示する。

## 開発品質と安全性

- 変更前に `AGENTS.md` と関係する既存テスト・マスター・コードを確認する。問題の原因を調べ、実装完了のための断定や憶測をしない。
- 新機能には **検証可能な受け入れ条件・回帰テスト**を追加する。既存機能の破壊、競合状態、タイムアウト、誤った状態保持、再送、UI取りこぼしをテストする。
- 対戦中の推奨はユーザーの現行構築・固定マスター・LIVE マトリクスを優先する。Champions にない他作品の仕様で補完しない。自動キャプチャと API の最適化は **勝率・締切・クレジット/トークン消費**の実測で評価する。
- LIVE 中の4ファイル再読込・Web検索は禁止。選出時は6行一括取得、選出後40秒PREPは18対面と勝ち筋3点を満たす。対戦中の行動選択と戦術判断は AI が行い、ローカルロジックが勝手な戦術フォールバックを作らない。
- スクリーンショットの収集、API送信、キャンセル、タイムアウト、古い結果の表示には安全策を設ける。ユーザーの明示的同意のないゲーム操作・秘密情報の書き出しはしない。
- Windows CI の synthetic/offscreen テスト、BlueStacks 実機キャプチャ、ChatGPT接続実測、ランクマの戦術精度は **異なる検証段階**であり、相互に代用できない。
- リスクのある変更は別コミット/PRで切り分け、既存の動作保証やプライバシー方針を維持する。未確認の機能は未確認と報告する。

## 完了報告の必須項目

ユーザーへ完了を伝える前に、少なくとも **PRリンク、最新 HEAD SHA、CI runリンクと対象 SHA、最終結果、実際に検証した範囲、未検証事項** を示す。実装途中・CI未完了・古いSHAの成功は「完了」と表現しない。
