# Issue #99 — 選出＋PREPの90秒共有、AI依頼の置換、通知OCR

> 状態: Draft PR #107 の実装・レビュー用仕様（2026-10-29）。過去の `SELECTION_PREP_SHARED_87S.md` は履歴資料。

## 時間管理

- 選出画面を初めて確認した時刻が共有90秒の起点。選出10秒→PREP80秒、35秒→55秒、70秒→20秒。
- 選出提案は完成次第表示する。選出とPREPに独立55秒/40秒の強制終了を設けない。87秒での強制終了／最後の3秒の予約を廃止する。
- 90秒までにGUI表示できた完成結果だけ「ゲーム内時間の合格」とする。時計の目標超過だけでモデル通信をキャンセルせず、同じ画面に対する遅延結果は注意付きで使用できる。
- ターンのゲーム内操作は45秒。30秒目標／32秒警告は観測指標であり、通信・表示を停止する条件ではない。HTTPは別途有限タイムアウトを持つ。
- 相手初手が観測されたらPREPを止める。後着PREPを「事前評価完了」としない。

## AI依頼の置換・鮮度

- 本当に新しいAI依頼をディスパッチするときのみ旧未完了依頼を論理退役させる。古いQThreadの終了待ちで新依頼を塞がない。
- 同じ相手プレビュー／同じ判断窓の重複画面は新依頼を作らない。未確定OCR候補や時計の経過だけでは無効化しない。
- Qt GUIスロットは送信元ワーカーで古い結果・進捗・終了処理を区別し、現行の状態を上書きさせない。新しい戦術状態、ターン、強制交代、結果画面では妥当性と合法性を再確認する。
- リクエスト・試合・ターン・状態更新・無効化理由を安全なログへ記録する。ゲーム画像や認証情報をリポジトリに含めない。

## PREP完成基準

- 初手6対面と控え12対面の計18件に評価根拠があり、選出3匹の「温存役・積み/高速停止役・締め役」の3点がすべて確定した場合だけ完成。
- 18件キャッシュがあっても役割不足なら未完成とし、必要時はキャッシュを再評価せず役割に限り補完する。
- 相手未判明枠を捏造しない。5/6などは部分評価であり、完全評価と混同しない。

## 自動技選択通知とOCR

- 上部システム通知 `サーバーに入力が届かなかったため\n技が自動で選ばれました` を **独立した `system_message` ROI** で検出する。
- 正規化ROIは暫定 `(0.31, 0.085, 0.73, 0.19)`。実際のゲームviewportに対して正規化座標を使う。960×572および同一縦横比の別解像度で確認し、実機のプライベート較正が済むまで本番の確定通知には使わない。
- OCR信頼度0.90以上、正確な全文（空白・改行を正規化）を条件に `AUTO_MOVE_SELECTED_INPUT_NOT_DELIVERED` を記録し、そのターンの古いAI回答を無効化する。
- この表示は**タイマー切れの証拠ではない**。実際に使われた技を推定しない。後続の戦闘メッセージで確認する。
- 未較正・低信頼・異なる文言・画面レイアウト不一致の場合はイベントを確定しない。

## GUIテスト整理

- 単発画像をAIへ送る旧「イベント読み取りテスト」を削除。
- 「ローカルOCR診断（AI送信なし）」は維持し、タブ名を「ローカルOCR診断」に変更。
- イベント→状態更新→助言の連続性は「1対戦統合テスト」と実機ログで検証する。
