# ライブ画面同期・AI処理の優先順位修正（2026-10-26）

## 実戦ログで判明したこと
- 選出の画面認識完了まで内部は MATCHMAKING のまま動作し、選出結果の受信後に実選出を仮定して PREP へ移行した。
- CMD_MENU 認識後も同一付近の画面に対する AI 通信が複数回発生し、初手の技選択に間に合わなかった。
- ローカル画面分類候補・推論元時刻・送信待ち時間を区別する証拠が不十分であり、実際のゲーム時計の読取は検証されていない。

## 変更した制御
1. 一定の MATCHMAKING 静止画像を周期的に再送信するフォールバックを廃止。最初の1フレームと意味のあるシーン変化は引き続き認識する。
2. 分類器のラベル変化・確信度・マージン・遅延を画像なしでログに記録。UNKNOWN を OTHER とみなさず、繰り返し不明ならシーン変化フォールバックで観測を継続。
3. GPT通信中に観測した未分類画面変化を1つ保持し、モデル応答処理後に送信。先行選出への有効な提案は、後続の操作画面候補が到着しても捨てず、戦闘画面へ処理を進める。
4. 初めてローカル分類されたターン操作画面を時間起点として保持し、以後のモデル再試行が利用可能時間を増やさない。ゲーム内時計は未取得であり、ローカル観測時刻は推定値である。
5. PREP状態のGUIには18対面の構造上の確認、暫定ソース、実選出の未確認、部分的・未完成・期限超過の状態を区別して表示する。

## 元仕様の維持と限界
- 戦術判断そのものは OpenAI API が担当し、Pythonはポケモンの技・交代先を創作しない。
- キャッシュ18対面＋勝ち筋3点は形式上の充足であり、相手の技・安全受けなどを実機で保証しない。
- 選出モデルの3匹は提案であり、`selection_assumed` を実際のユーザー操作確定と混同しない。選出からPREPまでの共有87秒上限は維持。
- 画面分類器のONNX重みは新規作成せず、5分類・schema v2・検証済み重みの受け入れのみ。未配置の場合もログでわかる。旧7分類の画像・モデルと実戦画像を変更・公開しない。
- ローカル推論・API通信・画面遷移の同期を改善したものであり、実ゲーム45秒ターン内の成功率を保証しない。

## 回帰テスト項目
- マッチング同一画像が周期再送信されないこと。
- 選出モデルの結果より先に行動画面が検出されても選出提案を保持し、その後の行動画面を再評価できること。
- ターンのローカル観測起点が重複検出で後ろにずれないこと。
- 既存の分類器・キャッシュPREP・GUI連携の単体テストが通ること。

## Windows・実ゲーム追加受入項目
- 配置ONNXの診断表示 `MODEL_READY_CPU` 等を確認（`MODEL_NOT_BUNDLED` は推論利用不可を意味する）。
- 90秒選出と45秒ターンで、選出・PREP・先手・技一覧への到達時刻を実機動画とログで突き合わせる。
- 最新PR HEAD SHAに対するWindows CI全体と `desktop-windows-validation` の成功後に限りマージする。
- 実機確認なしで勝率向上・画面分類の実測精度・ターン期限達成を断定しない。
