# Issue #128 — OCR入口診断・任意画像保存・旧提案の誤再表示廃止

## 変更内容（対戦支援アプリ）

- OCRエンジンのREADYとOCRジョブの投入成功は別の状態。毎ターンの
  `LOCAL_OCR_TURN_SUMMARY` に `ocr_offers` および
  `ocr_reject_disabled/no_profile/bad_image/aspect/label/no_roi/unchanged/queue_full`
  を追加した。以前は入口で棄却しても `ocr_skipped=0` としか見えなかった。
- **任意、初期OFF**の「OCR診断用の実画像・ROI・認識文字をローカル保存」を追加。
  対戦監視を開始する前にONにすると、
  `<アプリデータ>/debug-logs/ocr-captures/capture-<ID>/`
  に実キャプチャPNG、同フレームのROI PNGとメタデータJSON、
  OCRが実際に完了した場合だけ `ocr-results.jsonl` を記録する。
  **OCRが1件も投入されない場合も**サンプル元画像と拒否理由が残る。
- 診断画像は最大32サンプル／試合、保存容量24MiB／試合、直近5試合。
  PNGエンコード・ROI切り出しとファイル書き込みはデーモンワーカーに分離し、
  呼び出し側は最大4件の非同期キューにだけ投入する。キュー満杯の診断フレームは
  破棄し、対戦入力時間を待機させない。
- **画像・生OCR文字列は秘密情報を含み得る。** この保存は明示的な任意操作で、
  ローカル限定。GitHub・CI・配布ファイルへアップロードしない。共有前に内容を確認。
  通常の自動デバッグログは引き続き元画像を保存しない。
- 960×572サンプルROIは実機表示領域の正しさを保証しない。
  `profile_compatible=false` や `ASPECT_RATIO_MISMATCH` の証拠を
  保存しても、無検証に縦横比制限を外さず、Android→Windowsミラーリングの
  実キャプチャに合わせて表示領域・余白・ROIを別途校正する。

## 同ターンの通常交代画面

- 通常交代のGPT回答は一度だけ表示する。
- 回答採用時には `source_active`、`target`、`source_screen`、
  `turn_epoch`、`state_revision`、`ADVISED_NOT_CONFIRMED` を保持する。
  これは**交代が実行された証拠ではない**。
- 同一ターン・同じ現在ポケモン・行動解決やひんしの確認なし・状態版数一致
  という継続操作に限り、交代画面での二重GPT依頼を抑止。
  **前回の交代先をUIへ再表示しない。**
- 別の判断が必要な場合（技提案から手動交代／ひんし／行動解決／新ターン）や
  状態が矛盾している場合は以前の提案を流用せず、新しい判断へ進む。
  画像分類・イベント検出をすべて正確に行える保証はなく、実ゲームでの確認が必要。

## 監視停止

- `_stop_auto()` が `entries[-1]`（旧ADVICE等）を再描画する処理を廃止。
  `AUTO_STOPPED` を表示して旧行動を無効化する。
- 過去の回答の履歴は保持し、停止イベントだけで
  `GUI_DISPLAY.display_source=NEW_AI_RESPONSE` を発生させない。

## 対象外・検証限界

- 交代後の自軍アクティブ同定・技固定・次ターン合法性の根本修正は別課題。
  本修正だけでは、ゲーム側の実際の交代完了を検証したことにならない。
- OCRジョブ0件の**原因そのものは実キャプチャが未取得のため未確定**。
  次の実機診断でスクリーン寸法・ROI設定・OCRログを照合して特定する。
- 合成画像およびオフスクリーンGUIテストはWindows実機／ランクマ実戦の保証ではない。
