# 設計決定（2026-11-02）：Showdown全面採用を開発上の前提にする

対象：親Issue #138／Phase 0 #139／Phase 1 #140／Phase 2 #141／Phase 3 #142。**ユーザーの明示的な方針変更**に基づく。これまでの「Champions全仕様の実機互換性と任意途中局面復元の証明が終わるまでPhase 1へ進めない」という停止条件を撤廃する。

## 決定事項（工程上の採用）
1. **Pokémon Showdown（固定Champions mod SHA `ccfaa20f32af363569cd21a9d501b2bc1ded26b1`）を、ローカル自動戦術システムのデフォルト計算・ターン遷移エンジンとして採用する。** 実装をShowdownベースで先に完成させる。個々の技・特性・アイテム・メガ・端数の事前独立照合が揃っていないことを、Phase 1/2/3 の**開発着手・コード統合の一律ブロッカーにしない**。
2. 目標を、画面取得→認識→状態管理→合法手生成→Showdownによる局面計算→選出／PREP／各ターンのローカル自動判断→Windows GUIへの推薦提示までの**自動化**とする。現行OpenAI API経路は段階移行中に残し、主判断をGPT待ちに依存しない。Shadow稼働は有用な試験手段だが、全機構の実ゲーム互換「証明」やShadow長期実績を開発開始条件・全体完了条件にしない。
3. 運用開始後にChampions実ゲームと計算・状態遷移の不一致が見つかったら、**入力証拠→影響範囲→修正→回帰テスト→次戦適用**のループで継続改善する。ユーザーの最新ゲーム内確認・公式・Champions固定マスターの確定情報がShowdownと矛盾した際は、証拠を残してChampions側を優先し、Showdownモジュール／変換層の対象箇所に補正を実装する。既存で未観測の過去行動や相手のセットを事実として創作しない。
4. Phase 0の科学的評価は**書き換えず**、`Gate A=UNKNOWN`、`Gate B=UNSUPPORTED`、既存の「全面互換を証明できたか」判定`NO_GO`を歴史的検証結果として保持。新たに**`ENGINE_SELECTED_FOR_IMPLEMENTATION=SHOWDOWN_ASSUMED`／`DEVELOPMENT_BLOCKED_BY_PARITY_PROOF=false`**という独立の*ユーザーが受容した開発リスク*を記録する。**「ShowdownがChampionsと100%一致する」「実ゲーム完全復元済み」とは報告しない。**
5. Phase 1 Draft PR #144は、現行契約・CI・レビューを満たすなら開発を再開してよい。Phase 0が`UNKNOWN/UNSUPPORTED`だからという理由**だけ**でマージを禁止しない。ただしPR最新HEADの必須Linux/Windows CI、動作受入条件、合法手・現状態整合、プライバシー等の**ソフトウェア品質条件は緩めない**。本決定はPR #144の自動マージ承認ではない。

## 実装時に守る最低限の動作安全（「互換性の事前証明」とは別）
- 入力：使用可能ポケモン／習得技／持ち物／選出枠／技固定／PPなどの**Championsマスターに基づく合法性**を守る。画面で見えない相手の技・特性・配分は仮説として計算に使っても、観測確定として上書きしない。前回の個体・別ターンの情報を引き継がない。
- 出力：最新`match_id`、`decision_window_id`、`state_revision`、残り時間／画面種別・合法手を検査し、古い応答や使用不能な技・交代先を表示しない。入力自体が破損・矛盾・未対応のときは、「推測で確定表示」せず明示的な再取得・保留・安全な既存経路への切替を行う。
- 運用：固定Showdown SHAは対戦中に更新しない。技の実測ダメージや特性イベントの差は、証拠とともに該当ケースを記録し、対戦外に修正・テストして**次戦から**適用する。重大な誤動作時は機能単位の無効化／前版へのロールバックを可能にする。確定KOや安全受けは**計算モデル上の予測**と区別して表示する。
- Windows同梱Node workerのオフライン実行、IPCクラッシュ／期限切れ、状態リビジョン、GUI締切、セキュリティ・配布ライセンスは**製品として動くために必要な実装・CIタスク**であり、継続する。ただしChampionsの全技の事前検証を前提にしない。
- 目標は**支援アプリの自動判断**。ゲーム端末への自動タップ／入力操作は、従来どおり別Issue #91 のスコープとし、別途明示的な許可とゲーム規約等の確認なしには追加しない。

## 優先する開発順
1. Phase 1 #140：Showdown worker・状態契約・既存合法手検証器との共通化・自軍技／AP／選出3匹の伝達。
2. Phase 2 #141：3匹全体の勝ち筋、選出／18対面PREP、各ターン候補評価を**ローカルShowdown前提**で実装。未知相手の複数仮説と行動期限を扱い、推奨はユーザーに自動表示する。
3. Phase 3 #142：既存PySide6/Androidミラー認識への接続、Windowsオフライン配布、E2E・異常時回復、選択的運用フラグと差分記録。完成後の対戦ログで継続改善する。
4. Phase 0 #139：互換性監査を**開発停止ゲートから継続的な差分・既知リスク台帳へ**移す。すでに構築済みの合成PoC成果は保持し、実測と異なる箇所を見つけたときに優先修正する。

## 記録と成功基準
- 記録項目：実ゲームでの観測とShowdown予測、観測可能な相手状態、型仮説、結果差異、影響する行動推奨、修正PR、再発防止テスト。1試合の一致や不一致から全互換や勝率改善を断言しない。
- **製品開発の成功**：Windowsで自動観測・状態管理・Showdownベースの選出／PREP／ターン判断が操作期限内に表示され、合法性・旧結果排除・異常回復・オフライン配布が機能すること。
- **ゲーム互換性の評価**：別途`UNKNOWN`、`SOURCE_CONFLICT`、実ゲームの一致／不一致を維持する。互換性未証明を*開発停止*には使わないが、*互換性確認済みと宣伝する理由*にも使わない。

この決定は、以前のPhase 0 NO_GOの**証拠上の内容を否定するものではなく、ユーザーが不確実性を受け入れ、完成優先へ設計判断を変更したもの**である。古いIssue/文書の「Phase 0合格までPhase 1着手禁止」と矛盾するときは、開発着手条件についてのみ本決定を優先する。
