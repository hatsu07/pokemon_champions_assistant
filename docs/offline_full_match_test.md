# 保存画像によるマッチング～対戦終了のAI機能テスト

これはWindows GUIから、保存済み画像を順番に送信してChatGPTの画像認識と戦術提案経路を検証する**手動・読み取り専用**の機能です。ゲーム操作、クリック、キー入力、自動スキャンは行いません。

## 操作

1. 設定の「自軍構築」で使う6匹の構築を登録・検証し、「次戦に選択」→画面下の保存を行う。
2. 設定→ChatGPT→「ChatGPTでログイン・認識実測を開く」を選ぶ。ログイン済みならモデルが自動復元される。
3. 「マッチングから対戦終了までのAI再現テスト」を開き、「新しいテスト対戦を開始（4ファイル事前読込）」を押す。4ファイルはこの時点で1回だけ読み込み、同一の再現セッションで再読込しない。
4. マッチング画面の保存画像を指定して「この画像を送信してAI判断」。
5. 次に選出画面の画像を送信。**相手6匹と自軍6匹を照合**し、選出3匹＋初手が提示される。異なる構築のLIVEマトリクスしかない場合、**TEST_ONLY（機能試験のみ、戦術評価未検証）**と表示する。
6. 「実際に使った3匹と初手」を入力・確認し「実際の選出を確定」。モデルが選んだ3匹をゲーム内で確定したと**自動推定しない**。
7. 「選出後の40秒PREPをテスト（18対面）」を押す。構築専用LIVEマトリクスがない場合、**PREP_UNAVAILABLE**と記録して実戦評価を実行しない。互換マトリクスがある場合のみ、18対面・勝ち筋3点をAIに要求し、形式を検証する。形式合格だけでは戦術的正しさを保証しない。
8. 自分と相手の初手が映った画面→技選択→行動結果→交代先選択→次ターンの画像を順番に送る。選出で選んでいないポケモンや、画面に存在しない技・交代先は表示しない。画面で読めなかった情報は確認不能扱い。
9. 勝敗画面の画像を送信し、**勝利／敗北の表示が確認できたとき**にセッションを終了する。
10. 必要に応じ「テストログをJSON保存」を選ぶ。画像データとログイン資格情報はJSONに含めない。

## 画面種別と応答

| 画面 | 処理 |
|---|---|
| マッチング | 画面認識・セッション開始 |
| 6匹選出 | 相手6匹＋自軍6匹認識、選出3匹・初手の候補 |
| コマンドメニュー | 対面・画面状態の読み取り（未表示の技は推測しない） |
| 技選択 | **その画面に表示され、登録済みの技**から推奨 |
| 手持ち（通常交代／瀕死／交代技後） | **実際の選出3匹に含まれ、画面に表示される交代先**から推奨 |
| 行動結果 | 画像で確認できたダメージ・メッセージ・能力変化候補を記録。推薦した技を使ったと仮定しない |
| 詳細表示 | 表示された情報の確認 |
| 勝敗表示 | 勝敗が読み取れた場合だけ終了解析へ |

## 現在の制約

- このPRは保存画像の手動機能テストまで。リアルタイム自動キャプチャ→自動判定→AI回答の連動にはまだ接続していない。
- 自軍構築がLIVEマトリクスと異なる場合、戦術的な正解を意味する助言をしてはいけない。TEST_ONLYはあくまでAPI・画面・選択の通し試験。
- 画面ごとの画像認識・判断を35秒で打ち切り、PREPは別枠の40秒。画像が読み取れない、表示技／交代先を確認できない場合は安全側に停止。
- ゲーム中の情報ではなく**画像認識モデルによる未検証の観測候補**であり、実測精度は実機テストで確認する必要がある。
- 同じ画面を複数回送信すると、その都度モデルを呼び出す。テストが終わったら新しいテスト対戦を開始する。
