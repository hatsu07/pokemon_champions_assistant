# Issue #78 — イベント画面中にだけ行う非同期ローカル文字認識

## 方針と境界
- キャプチャは既存の300msタイマーを再利用し、追加キャプチャ・追加ChatGPT APIリクエストは行わない。
- ONNX が `BATTLE_EVENT` と判別したフレームのROI変化をQtスレッドで軽く比較する。別のdaemonワーカーでメッセージ・自軍HP分数・相手HP割合を日本語Tesseract OCRで読む。
- **タイマーROI (`TIMER` / `turn_command_timer`) は決してOCRしない。** `TURN_ACTION` / `SWITCH_SELECTION` でもOCRを実行しない。行動選択45秒は画面検出のローカルクロックで制御し、文字でタイマーを読まない。
- 複数イベントは有界キューに入れ、同じROIが変化しない場合は重複を除外。キュー満杯・認識不能・実行環境不備・不正ROI・ワーカー例外は観測候補なしとして継続する。
- 最新の認識済み候補はイベント時刻・フレームID・ROI・OCR信頼度・出典を添えてローカルメモリに保持する。現在のHP、状態異常、持ち物、フォーム、天候、技の効果などを確定したものとは**みなさない**。
- `COMMAND_MENU` 等の操作画面が検出されたら、完了分を直ちに取り出し、OCRワーカーを非同期停止する。新しいOCRやタイマーOCRが45秒の戦術要求を遅らせることはない。
- 次の戦術要求は既存の登録技4つ＋利用可能な控え0～2匹と、観測済みの状態、ローカルOCR候補、必要なイベント画像を1回で渡す。未確認事項があればChatGPT側に不明を維持させる。
- モデル未設定の低頻度画像変化検出では、イベントと誤認したOCR文字列を確定しない。イベント画像を送る従来の代替処理を保持する。

## 利用条件
- 既存のWindows配布には `pytesseract` は入っているが、`tesseract.exe` および日本語学習データ `jpn.traineddata` は別途必要。どちらかが欠ける場合、OCR停止を記録して画像支援を維持する。
- `calibration/screen_fields.json` に独立したユーザー検証済みROI設定があれば優先する。現状の960x572サンプルROIは実戦で未検証のため、すべて **候補**。
- OCR処理のタイムアウトは1.2秒。処理が詰まった場合は、次の操作画面を優先して未完了分を破棄する。

## 実機での受入検証（未実施）
ユーザー提供の実機画面・録画で、重要イベントの取りこぼし率、OCR誤確定0件、認識時間、45秒ターンの助言時間、イベント画像送信枚数、クレジット消費を計測する。日本語OCR学習データのWindows同梱／著作権・サイズは検証後に検討する。アイコン・HPゲージは既存の候補認識モジュールと実機キャリブレーションが必要であり、現段階で自動的な確定解析を主張しない。
