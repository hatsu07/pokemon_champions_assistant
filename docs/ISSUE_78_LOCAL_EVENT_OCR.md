# Issue #78 — イベント画面中にだけ行う非同期ローカル文字認識

## 方針と境界
- キャプチャは既存の300msタイマーを再利用し、追加キャプチャ・追加ChatGPT APIリクエストは行わない。
- ONNX が `BATTLE_EVENT` と判別したフレームのROI変化をQtスレッドで軽く比較する。別のdaemonワーカーでメッセージ・自軍HP分数・相手HP割合を日本語Tesseract OCRで読む。
- 選出一覧 (`selection_own_list` / `selection_opponent_list`)、交代一覧・詳細 (`switch_party_list` / `switch_detail_panel`)、上部システム通知 (`system_message`：入力未到達・技の自動選択通知等) はOCR対象から除外する。選出と交代の既存画像認識は維持し、古いローカル校正ファイルにこれらのROIが残っていてもOCRしない。
- **タイマーROI (`TIMER` / `turn_command_timer`) は決してOCRしない。** `TURN_ACTION` / `SWITCH_SELECTION` でもOCRを実行しない。行動選択45秒は画面検出のローカルクロックで制御し、文字でタイマーを読まない。
- 複数イベントは有界キューに入れ、同じROIが変化しない場合は重複を除外。キュー満杯・認識不能・実行環境不備・不正ROI・ワーカー例外は観測候補なしとして継続する。
- 最新の認識済み候補はイベント時刻・フレームID・ROI・OCR信頼度・出典を添えてローカルメモリに保持する。現在のHP、状態異常、持ち物、フォーム、天候、技の効果などを確定したものとは**みなさない**。
- `COMMAND_MENU` 等の操作画面が検出されたら、完了分を直ちに取り出し、OCRワーカーを非同期停止する。新しいOCRやタイマーOCRが45秒の戦術要求を遅らせることはない。
- 次の戦術要求は既存の登録技4つ＋利用可能な控え0～2匹と、観測済みの状態、ローカルOCR候補、必要なイベント画像を1回で渡す。未確認事項があればChatGPT側に不明を維持させる。
- モデル未設定の低頻度画像変化検出では、イベントと誤認したOCR文字列を確定しない。イベント画像を送る従来の代替処理を保持する。

## 利用条件
- 既存のWindows配布には `pytesseract` は入っているが、`tesseract.exe` および日本語学習データ `jpn.traineddata` は別途必要。どちらかが欠ける場合、OCR停止を記録して画像支援を維持する。
- `calibration/screen_fields.json` に独立したユーザー検証済みROI設定があれば優先する。現状の960x572サンプルROIは実戦で未検証のため、すべて **候補**。
- OCR処理のタイムアウトは1.2秒。処理が詰まった場合は、次の操作画面を優先して未完了分を破棄する。

## 実機での受入検証（未実施）
ユーザー提供の実機画面・録画で、重要イベントの取りこぼし率、OCR誤確定0件、認識時間、45秒ターンの助言時間、イベント画像送信枚数、クレジット消費を計測する。日本語OCR学習データのWindows同梱／著作権・サイズは検証後に検討する。アイコン・HPゲージは既存の候補認識モジュールと実機キャリブレーションが必要であり、現段階で自動的な確定解析を主張しない。

## テキスト優先認識（30秒応答目標との統合）
- イベント検知ごとにローカルの非同期OCRキューへ投入し、OCRが完了したテキスト／HPは**イベント表示中に**`LocalBattleStateTracker`へ保存。行動選択画面で新たにOCRを起動・待機しない。
- 日本語Tesseract 5の実行ファイルと `jpn.traineddata` / `eng.traineddata` をWindows DEVELOPMENT GUIのZIP内の `ocr-runtime` に配置する。`TesseractJapaneseOcr` はまず同梱実行ファイルを検出し、ユーザーの別途導入なしで利用できることをCIで確認する。実行できない・日本語辞書が欠ける場合はOCR候補を確定に昇格せず画像で補完する。
- 参照解像度と縦横比が一致する高解像度キャプチャは、相対ROI座標を適用してOCR領域を960×572相当のサイズに縮小。ただし画面のキャリブレーションは実機未検証なので、OCR結果の`game_validated`は自動的にtrueにしない。
- 直近イベント画像にはローカル`capture-<frame_seq>`と対応づける。すべてのイベント画像に信頼度0.90以上の文字メッセージOCR結果があり、ユーザーによる実画面ROI校正があり、OCR実行時のキューあふれ・廃棄・未処理・エラーがゼロの場合にのみイベント画像を送らない。
- 上記に満たない場合は従来どおりイベント画像最大2枚を補助的に送り、現在の操作画面は常に1枚送る。機械的に画像を全廃すると現在の対面・メガ・HP・技・交代画面の把握を誤る危険があるため実施しない。
- 画像添付の理由は`EVENT_IMAGE_TEXT_FIRST_DECISION`のログで確認できる。ChatGPTは確定済み戦闘状態と`local_field_candidates_unverified`を受け取り、OCR候補を確定情報に昇格させない。
- 戦術判断の応答目標はユーザー指定の**30秒**、暫定的な表示最終期限は32秒。実ゲーム45秒に正確同期しているわけではない。APIへの画像枚数が削減されれば応答速度が改善する可能性はあるが実戦検証が必要。
- バトルイベントをテキストとして読み取ったことは「イベントの効果がChampions仕様で確定した」と同義ではない。技・持ち物・特性・能力変化の確定的な更新には実戦文面の検証を必要とする。Issue #78の未検証項目として保持する。
