# Issue #102/C — ターンOCR入力の有界化（ローカル台帳は非破壊）

## 目的
未処理OCRが365件に累積しても、ターンGPTのリクエストに365件の原文を毎回添付しない。
ローカルの LocalBattleStateTracker の原本、未処理・不確実な根拠、
確認済み battle_evidence、合法技とベンチ、メガ・こだわり等は変更しない。

## 仕様
- OCR取得・同一フレーム重複除去は既存どおり。新モジュール
  `ocr_turn_context.build_ocr_turn_context` がAPI送信用の独立ビューを作る。
- 最大112行/ターン。前回までの未解決質問（出典フレームつき）を先に扱い、
  未提示の新規イベントと古い未提示 backlog を順次送信する。
- GPTは従来どおり**同じ1回**の `AI_OCR_TURN_SCHEMA` 応答に、
  行動・根拠つき確定更新・処理済みフレーム・最大16件の未解決質問を返す。
  質問は戦闘事実ではなく `verified=False` で持ち越し、元フレームIDを必須とする。
- 安全確認は従来の `apply_ai_ocr_updates` を使用。GPTが生成した疑問の文面を
  ローカルコードで技・持ち物・ポケモンの確定情報へ変換しない。
- 未提示行は次回優先取得でき、既に提示された未確認原文もローカル台帳に残る。
  同一フレームの一部しか送っていない場合はフレーム一括ACKを拒否する。
- 診断ログは原文を含まず、元件数/送信件数/未送信件数、
  JSONの送信前後byte数、未解決件数、部分送信フレーム数のみ記録する。

## テスト・制約
- `tests/test_ocr_turn_context.py` は**合成データ**365件で、
  上限・台帳非変更・元証拠ID・追加のGPT呼出しなしを検査する。
- Windows CIは本モジュールをオフライン実行。実ゲーム由来の多ターン履歴
  と p50/p95、32秒警告、45秒入力期限内達成率は実機データで別途比較が必要。
  合成データの成功を実戦の時間短縮と断定しない。
- 過去のOCR原文や試合画像を診断ログへ保存しない。
