# Issue #102/C — GPTが必要なOCR証拠を選んで次ターンへ持ち越す

## 期待仕様（ユーザーフィードバックに基づき修正）

OCR件数で機械的に切る方式ではない。最大112件・旧未解決32件・
矛盾8件・未解決質問16件といった**固定割当は採用しない**。

- 最初の戦術GPT要求には、そこまでに取得した**未提示の新規OCR全件**を渡す。
  たとえ365件であっても件数を理由に削らない。
- GPTは既存の**同じ1回の行動判断応答**で、戦闘状態の更新、
  根拠付き処理済みフレーム、次ターンも必要な未解決事項
  `pending_ocr_questions` を返す。追加の要約用GPT要求は作らない。
- 次のターンは、検証済みの `battle_evidence` や登録4技・選出など
  **現在状態**、前回GPT判断後の**新規OCR全件**、
  **前回GPT自身が持ち越しを選んだ未解決質問と元フレームの証拠行**
  のみを渡す。前回渡したが次ターンには不要と判断された行は再送しない。
- 技固定・先制技・積み・観測S・メガ・HP・相手交代等について、
  GPTが未確定で重要と判断したものを出典フレームと再検証条件付きで残す。
  既存の証拠強度・合法性検証を通っていないOCRは確定事実に変換しない。
- `LocalBattleStateTracker` は元のOCRを失わず保存する。GPTが持ち越し
  対象に選ばなかったOCRも**ローカルにはUNVERIFIEDのまま残る**。
  `_ai_ocr_presented_keys` は「GPTに見せた」だけの記録であり、確認済み
  という意味ではない。`_ai_ocr_ack_frames` は既存の確定処理済み管理。
  これらを混同しない。
- GPTから出典不明の持ち越し質問が返っても証拠として採用しない。
  自軍現在ポケモンの整合が崩れた場合は提示済み状態を戻し、
  行動ブロックによる未確認証拠の消失を防ぐ。
- 画像フォールバック用モデルの入力圧縮は本変更へ混在させず、
  従来の一回リクエスト経路を維持する。

## 計測・検証

`OCR_TURN_COMPACTION` には、ローカル全件・新規件数・再送する
GPT選択証拠件数・前回までの証拠の未再送件数・JSONバイト長を記録する。
各OCR原文や画像を診断ログへ追加しない。
`OCR_TURN_TIMING` には、ワーカー内の送信前/AI通信/後処理時間、
最近64回のp50/p95、32秒警告・45秒目標の到達状況を記録する。
画面出現から実際のユーザー入力までの全工程とは別指標とする。

`tests/test_ocr_turn_context.py` では、365件全件の初回送信、
GPT指定の未解決証拠と新規分だけの次回送信、ローカル台帳非破壊、
捏造された出典の拒否、確認済みと未確認の混同防止、同一GPT応答での
持ち越し、状態矛盾時の再評価を**合成データ**で回帰確認する。

**重要な限界:** 最初のターンに未提示OCRが365件あれば、この設計では
365件を送る。そのターンの遅延短縮は保証できない。GPTが重要事項を
持ち越しから誤って落とす危険も残るため、実戦ログ上の誤脱落・
所要時間・32秒警告・45秒期限内成功率を別途確認する必要がある。
CI成功と実ゲームでの対戦支援成功を同一視しない。
