# Issue #92 — 対戦後・自律改善研究 Phase 1（未検証候補の蓄積）

> 2026-10-29。Issue #92 全体の実装完了を意味しない。今回のPRは **P1–P3のうち試合後レビュー横断集計・未検証候補化の最小基盤**のみ。ゲーム自動操作はIssue #91の別スコープ。

## 実際に動く範囲

- 既存の1試合ごとのGPT対戦後レビュー（`postmatch_learning.request_review`）がSQLite保存に成功した後、同じ低優先度ワーカースレッドで `AutonomousImprovementStore.aggregate_after_review` を実行する。**追加API通信・モデル再学習を行わない**。
- `match_history`、`postmatch_reviews` から最大40試合分を参照し、**同じteam_idと同じteam_signatureの試合だけ**を集約する。
- 最低3つの異なる終了済み試合とレビューが必要。同一試合で複数の観測・仮説が出ても独立試合数として数えない。前回研究バッチから新たな3試合が揃うまで、追加バッチを生成しない。
- ポケモン・対象・問題ラベルが一致する反復GPT仮説を候補化し、出典試合ID、候補の文面、複数レビューの提案不一致、根拠の不明確さを記録する。モデルの回答はいつでも **GPT_HYPOTHESIS_UNVERIFIED**。実際に有効な選択肢や安全受けとみなさない。
- `matchup-learning.sqlite3` に `autonomous_improvement_batches` と `autonomous_improvement_candidates` を **CREATE TABLE IF NOT EXISTS** で非破壊追加。既存のreview/historyを改変しない。元の構築CSV・4ファイル・masters・LIVEマトリクスも一切編集しない。
- `history(team_id)` と `candidates(batch_sha)` で研究履歴を読み取れる。対戦後レビュー欄には新しい候補数（未検証・自動適用なし）を表示する。
- リサーチ集約中のエラーは対戦後レビュー保存成功を取り消さず、再現可能なステータスだけ返す。研究APIの読み込みはLIVE判断経路に接続しない。

## 保守的ゲート

- 研究候補の `legality=NOT_CHECKED`、`validation=DEFERRED_UNVERIFIED`、`promotion_status=NOT_AUTHORIZED` は変更不可。新しいルール、処理役、KO確定、受け性能への自動昇格は **禁止**。
- 3件以上の「同じ文面のGPT指摘」は、相関や因果・当時の可視情報・採用優位性の証明とは異なる。研究候補が存在することは、勝率改善を意味しない。
- 元のレビューの `OBSERVED_CANDIDATE` は確認済み事実に格上げしない。相手の技やS、ダメージ、持ち物を補完しない。
- 既存ログの後知恵、曖昧なOCR、異なる構築SHAの混合による戦術提案は自動採用しない。
- レビュー基盤側で保存される履歴に、各ターンの厳密な「当時見えていた情報」が無い場合、因果や安全択の判定をスキップする。新たな情報を捏造しない。
