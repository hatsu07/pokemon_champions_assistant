# 2026-10-27 OCR・瀕死交代・PREP・鮮度の修正と実機確認

PR #84。ユーザーの8項目に対応。外部OCR字幕やゲーム画面画像、正解テキストはGitHub/CIへアップロードしない。

## ① Tesseract実行と日本語辞書
- 配布版の `ocr-runtime` に同梱した実体と `jpn+eng` を明示使用する。
- `pytesseract` のグローバルコマンド変更を排除し、PNG一時ファイル→ネイティブCLI（`-c tessedit_create_tsv=1`、名前付き `configs/tsv` に依存しない）→UTF-8 TSVを直接処理する。配布用スクリプトで実際にTSVヘッダーが出ることも検査する。子プロセスに同梱tessdataを明示し、Windowsコンソールを非表示にする。一時画像は毎回削除する。
- `OCR_TESSDATA_LOAD_FAILED`, `OCR_LANGUAGE_UNAVAILABLE`, `OCR_PROCESS_START_FAILED`, `OCR_PROCESS_TIMEOUT`, `OCR_INVALID_TSV` 等の安全なコードを返す。実際のstderr・個人パスは保存しない。
- PR Windows CI のGUI起動スモークで、PyInstaller実行ファイルから同梱Tesseractを起動し、PNG→ネイティブCLI→TSV解析の成功を `OCR_NATIVE_EXECUTION_OK` として確認する。合成画像 `97%` の一致可否は `synthetic_numeric_recognized` として別途報告し、**文字認識の一致をOCRプロセス起動合格の条件に混同しない**。実画像・日本語の認識率はBlueStacks実機のOCR診断で別検証。非ゼロ終了、tessdata失敗、起動失敗、TSV不正などはCI失敗のまま。

## ② ローカルOCR専用テスト
「テスト全般」→「バトルイベント読み取りテスト」→画像選択→「ローカルOCR診断（AI送信なし）」。選出・PREP不要。実際のOCRエンジンとROIで、領域ごとに切り出し画像／文字／信頼度／解析候補／エラー／所要時間を表示する。既存の「イベント読み取りテスト」は引き続きChatGPT画像認識であり、別処理。

## ③ HP・瀕死・状態
- 確認済み `OUR_FAINTED` を該当自軍ポケモンのHP=0として記録する。次のポケモンの登場を確認するまで `awaiting_replacement` を維持する。
- OCRのHP・メッセージは最後に確認したポケモン名や認識名を*候補*として付けるが、OCRだけで生存・瀕死を確定しない。ROI単位で失敗を分離し、他ROIの成功を失わない。

## ④ 強制交代
`TURN_ACTION` のあと `SWITCH_SELECTION` を検出したら、BATTLE_EVENTを読み損なっていても別の判断画面として扱い、旧技表示を無効化する。AIへ `required_action_kind=SWITCH` を明示し、前のポケモンの技候補と推薦履歴を除外。AIがMOVE/PIVOTを返す、あるいはDETAIL_OVERLAYと誤認した場合は交代提案を捏造せずBLOCKEDにする。

## ⑤ ROI・精度
提供済みの実画像5枚（960×572）をオフライン検証した。日本語メッセージは元画像が比較的安定。相手特性ポップアップは2x拡大で改善、相手HP 97%はROI絞り込み＋engのPSM7・数字記号限定で安定した。自軍HPの小さなスラッシュは誤認識が残るため、数字を勝手に推測補完しない。高解像度ROIを無条件で960基準へ縮小しない。別解像度・別UIの検証は未実施。

## ⑥ API送信最適化
SWITCH選択は確認済み状態と控えの登録技だけを渡す。以前の技提案履歴を除去する。確認済み瀕死がある場合は過去BATTLE_EVENT画像の再送を避け、現在の交代メニュー画像だけで表示された候補を確認する。状態不足やOCR失敗時は画像による補完が必要になる場合がある。完全なテキストのみの判断は正しい候補確認が得られた場合に限る。

## ⑦⑧ PREPと回答鮮度
PREPの40秒経過はソフト警告にし、モデル結果を破棄しない。PREPの結果が完成しても規定時間超過というだけで捨てず、新しいAI送信が実際に始まった場合だけキャンセルする。明示停止は例外。正常な提案履歴は残すが次の判断として再利用しない。API自体の通信エラー・有限タイムアウトは別の失敗であり、応答が未生成なら完成扱いにしない。
